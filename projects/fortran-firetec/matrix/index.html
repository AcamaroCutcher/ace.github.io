Built-in matrix operations

matmul(A, B), transpose(A) and dot_product(x, y) are part of the language. A * B is not a matrix product: it multiplies element by element. Note also that reshape fills a matrix column by column, so a matrix typed in row by row needs a transpose.

matrix.f90
! matrix.f90 -- matrix algebra: matmul, transpose, dot_product, and solving A x = b by Gaussian elimination
program matrix
  implicit none
  integer, parameter :: wp = kind(1.0d0), n = 3
  real(wp) :: a(n, n), b(n), x(n), c(n, n), r(n)
  integer :: i

  ! Fortran fills reshape column by column; transpose to write the matrix by rows
  a = transpose(reshape([ 4.0_wp, -2.0_wp,  1.0_wp, &
                         -2.0_wp,  4.0_wp, -2.0_wp, &
                          1.0_wp, -2.0_wp,  4.0_wp], [n, n]))
  b = [11.0_wp, -16.0_wp, 17.0_wp]

  print '(a)', 'A ='
  do i = 1, n
    print '(3f8.2)', a(i, :)
  end do
  print '(a, f8.2)', 'dot_product(b, b) = ', dot_product(b, b)
  c = matmul(a, transpose(a))
  print '(a)', 'A A^T ='
  do i = 1, n
    print '(3f8.2)', c(i, :)
  end do

  x = solve(a, b)
  print '(a, 3f10.5)', 'x        = ', x
  r = matmul(a, x) - b
  print '(a, es10.2)', '|A x - b| = ', sqrt(dot_product(r, r))

contains

  ! Gaussian elimination with partial pivoting; returns the solution, leaves a and b unchanged
  function solve(a_in, b_in) result(x)
    real(wp), intent(in) :: a_in(:, :), b_in(:)
    real(wp) :: x(size(b_in))
    real(wp) :: m(size(b_in), size(b_in) + 1), row(size(b_in) + 1), f
    integer :: k, p, j, nn
    nn = size(b_in)
    m(:, 1:nn) = a_in
    m(:, nn + 1) = b_in
    do k = 1, nn - 1
      p = maxloc(abs(m(k:nn, k)), dim=1) + k - 1      ! pivot: largest entry in column k
      if (p /= k) then
        row = m(k, :); m(k, :) = m(p, :); m(p, :) = row
      end if
      do j = k + 1, nn
        f = m(j, k) / m(k, k)
        m(j, k:) = m(j, k:) - f * m(k, k:)            ! eliminate below the pivot
      end do
    end do
    do k = nn, 1, -1                                  ! back substitution
      x(k) = (m(k, nn + 1) - dot_product(m(k, k + 1:nn), x(k + 1:nn))) / m(k, k)
    end do
  end function solve

end program matrix

Implicit methods and tridiagonal systems

Time-stepping schemes that are implicit (they use the unknown future values on both sides) stay stable with long time steps, but every step needs a linear solve. In one dimension the matrix is tridiagonal and the Thomas algorithm solves it in O(n) operations. Heat conduction into a fuel bed, below, takes a 0.5 s step at which the explicit scheme would blow up (r = κΔt/Δx² = 12.5, far above the explicit limit of 0.5). FIRETEC's method of averages treats the fast pressure terms on small steps for the same reason: stability.

thomas.f90
! thomas.f90 -- implicit (backward Euler) heat diffusion through a 1-D fuel bed, solved with the tridiagonal (Thomas) algorithm
program thomas
  implicit none
  integer, parameter :: wp = kind(1.0d0), n = 50
  real(wp), parameter :: kappa = 1.0e-4_wp, dx = 0.002_wp, dt = 0.5_wp
  real(wp) :: t(n), lo(n), di(n), up(n), rhs(n), r
  integer :: step, i

  t = 300.0_wp
  r = kappa * dt / dx**2                 ! = 12.5: an explicit scheme would blow up, an implicit one is stable
  lo = -r; di = 1.0_wp + 2.0_wp * r; up = -r
  ! fixed temperatures at both ends: a hot face at 900 K and the far side at 300 K
  di(1) = 1.0_wp; up(1) = 0.0_wp; di(n) = 1.0_wp; lo(n) = 0.0_wp

  do step = 1, 20
    rhs = t
    rhs(1) = 900.0_wp; rhs(n) = 300.0_wp
    call tridiag(lo, di, up, rhs, t)
  end do
  print '(a, f5.1, a)', 'after ', 20 * dt, ' s:'
  do i = 1, n, 7
    print '(f7.3, a, f8.2, a)', (i - 1) * dx * 100.0_wp, ' cm  ', t(i), ' K'
  end do

contains

  ! solve  lo(i) x(i-1) + di(i) x(i) + up(i) x(i+1) = d(i),  i = 1..n  (lo(1) and up(n) unused)
  subroutine tridiag(lo, di, up, d, x)
    real(wp), intent(in)  :: lo(:), di(:), up(:), d(:)
    real(wp), intent(out) :: x(:)
    real(wp) :: c(size(d)), g(size(d)), m
    integer :: i, nn
    nn = size(d)
    c(1) = up(1) / di(1)
    g(1) = d(1) / di(1)
    do i = 2, nn                          ! forward sweep
      m = di(i) - lo(i) * c(i - 1)
      c(i) = up(i) / m
      g(i) = (d(i) - lo(i) * g(i - 1)) / m
    end do
    x(nn) = g(nn)
    do i = nn - 1, 1, -1                  ! back substitution
      x(i) = g(i) - c(i) * x(i + 1)
    end do
  end subroutine tridiag

end program thomas

LAPACK

For real work, call LAPACK (and BLAS underneath it): decades-old, heavily optimized Fortran libraries. dgesv solves a general system by LU factorization; dgtsv is the tridiagonal solver; dsyev computes eigenvalues. On clusters link OpenBLAS or Intel MKL.

lapack.f90
! lapack.f90 -- the same 3x3 system with LAPACK's dgesv (LU factorization with partial pivoting)
! build:  gfortran lapack.f90 -llapack -o lapack      (on clusters: -lopenblas, or -qmkl with Intel)
program lapack_demo
  implicit none
  integer, parameter :: n = 3
  double precision :: a(n, n), b(n, 1)
  integer :: ipiv(n), info

  a = transpose(reshape([ 4d0, -2d0,  1d0, &
                         -2d0,  4d0, -2d0, &
                          1d0, -2d0,  4d0], [n, n]))
  b(:, 1) = [11d0, -16d0, 17d0]
  call dgesv(n, 1, a, n, ipiv, b, n, info)   ! on return b holds x, and a holds the LU factors
  if (info /= 0) stop 'dgesv failed'
  print '(a, 3f10.5)', 'x = ', b(:, 1)
end program lapack_demo
