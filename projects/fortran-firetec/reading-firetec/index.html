Reading and running FIRETEC

A guided tour of the HIGRAD/FIRETEC source: the main loop, the state arrays, a physics routine, the build, the input file and first changes.

Get and build the code

Clone and build FIRETEC-1.5.1
git clone https://github.com/lanl/FIRETEC.git
cd FIRETEC/CODE-1.5.1
mkdir build && cd build
cmake ..                       # -DDBL_PREC=ON: double precision;  -DDEBUG=ON: -Wall -fcheck=all
make -j 8                      # the executable is ./firerad

The build needs gfortran (or Intel or Cray Fortran), MPI and CMake. CMake builds each physics package (Vegetation, Radiation, subGridTurb, Firebrands, Emissions, …) as a library and links them into firerad.

Read the main loop first; it is in Section 15. Then follow one variable: search for irhof (the fuel density index) with grep -rn irhof . and you will find where fuel is read, burned and written.

Reading a physics routine

Here is the heart of the burning routine, with the Fortran from this course marked. Every line maps to an equation in Section 15.

FIRETEC-1.5.1, Vegetation/burn_veg.F90 (excerpt)
  do k=1,lls                                   ! nested loops, first index innermost (Lesson 03)
    do j=jl,ju
      do i=il,iu
        do ift=1,nfuel
          rkctemp=0.2_wp*xv(i,j,k,ikb)/xv(i,j,k,irho)      ! kind suffix _wp (Lesson 02); named indices (Lesson 04)
          sigmac=sc*0.5_wp*sqrt(rkctemp)
          call computePsif(psif,temps(ift,i,j,k))          ! a subroutine returning psif (Lesson 06)
          percHydroRemaining=max(0.0_wp,(xvfuel(ift,i,j,k,irhof) &
            -hydroThresh*rhoFuelinitial(ift,i,j,k)) &
            /(rhoFuelinitial(ift,i,j,k)*(1.0_wp-hydroThresh)))
          cf=cfhydro*percHydroRemaining+cfchar*(1-percHydroRemaining)
          slambdaof=sum(xvfuel(:,i,j,k,irhof))*xv(i,j,k,iO2) &     ! sum over a section (Lesson 04)
            /(sum(xvfuel(:,i,j,k,irhof))/rnfuel+xv(i,j,k,iO2)/rno)**2
          ff=cf*xvfuel(ift,i,j,k,irhof)*xv(i,j,k,iO2)*sigmac*psif* &
            slambdaof/(100.0_wp*sizescale(ift,i,j,k)**2.0_wp)
          ! ... then forcings: fuel lost, heat to the solid and to the gas
          force_xvfuel(ift,i,j,k,irhof)=force_xvfuel(ift,i,j,k,irhof)-ff*rnfuel

Notice that the routine does not change xvfuel directly: it adds to a forcing array, and the solver applies all forcings together. That keeps the physics independent of the time-stepping scheme, as in Lesson 07.

Running a first case

A run reads gridlist (one name = value per line) from the working directory. Start from TOOLS/Gridlist/gridlist, a 50 × 50 × 20 grid on 2 × 2 processes, and the full list of options in TOOLS/Gridlist/GRIDLIST_OPTIONS.txt.

Run the example
mkdir run && cd run
cp ../TOOLS/Gridlist/gridlist .
mkdir -p comp                                  # outname = './comp/comp.out'
mpirun -np 4 ../CODE-1.5.1/build/firerad | tee log.txt

Every step prints the minimum and maximum of each field (the routine rmaxmin), which is the first thing to watch: NaNs or runaway values mean the time step or the inputs are wrong. A real burn also needs fuel files from LANL's Trees program and an ignition file; see TOOLS/Ignition.

Not run for this page These commands follow the repository's build files and example input; I have not run FIRETEC itself.
Exercises
  1. Build FIRETEC in debug mode (cmake .. -DDEBUG=ON) and in double precision, and compare the run time of the example.
  2. Find where nprocx and nprocy are checked against the number of MPI processes, and make a run fail on purpose to see the message.
  3. In burn_veg.F90, the drag coefficient cd and the mixing scale sc live in a module. Find it with grep.
  4. Add a line to compress.F90 that prints the total fuel mass every frqoutput steps. You will need MPI_Allreduce (Lesson 08).
