Multiple ignitions

Several fires at once, line ignitions, any number of ignition points from an arrival-time field, and ensembles for risk maps.

Background: 60 fires from this project's spread model on the WUI fuel map. It switches with light/dark mode.

Why more than one ignition

  • Several fires at once: an east-wind day with multiple starts (power lines, arson, spot fires). Fires interact through the atmosphere (one fire's in-draft pulls on the other) and through the fuel (merging fronts): the level set handles merging automatically.
  • Line ignitions: a firing operation along a road, or a power line failing over a distance.
  • Risk maps: many separate runs with one ignition each (an ensemble), the coupled-model version of Section 05's 2,000 fires.

Up to five: ignition lines in the namelist

The namelist has five ignition slots (…1 to …5); fire_num_ignitions says how many are used. A point is a line with start = end; a line ignites progressively from start to end at fire_ignition_ros between the start and end times.

Any number: ignition from an arrival-time field (fire_tign_in_time)

SFIRE can also ignite from a given field: with fire_tign_in_time > 0, every time step until that time it ignites each cell whose given time has passed, while the model keeps spreading the fire normally (ignite_from_tign_in in module_fr_sfire_core.F: tign = min(tign, tign_in), lfn = min(lfn, tign − t)). The given times come from TIGN_G in wrfinput, so any number of ignitions, each with its own time and size, is just a field to write:

$$T_{in}(\mathbf x) = \min_k \left\{ t_k : \lVert\mathbf x - \mathbf x_k\rVert \le r_k \right\}, \qquad T_{in} = \infty \ \text{elsewhere} \tag{1}$$

Rules from the code
  • Not together with ignition lines: “ignition from lines and from tign_in are not compatible”. Set fire_num_ignitions = 0.
  • Not together with fire_perimeter_time.
  • Give each ignition a radius of at least 1.5 fire cells (the script enforces it), and set fire_tign_in_time just after the last ignition.

Ensembles: one ignition per run

For a probability map like Section 05's, run many short simulations that differ only in the ignition (and, ideally, in the weather: several days, or members of an ensemble forecast). real.exe runs once; each member copies the input and writes its own ignition.

Slurm job array
#!/bin/bash
#SBATCH --job-name=sfire-ens
#SBATCH --array=0-19                       # 20 members, one ignition each
#SBATCH --nodes=1 --ntasks-per-node=64 --time=06:00:00
. ~/wrf-env.sh
M=$(printf "%03d" $SLURM_ARRAY_TASK_ID)
RUN=$SCRATCH/ens/m$M && mkdir -p $RUN && cd $RUN
ln -sf $HOME/WRF-SFIRE/run/* . && rm -f namelist.input
ln -sf $SCRATCH/ens/common/wrfbdy_d01 $SCRATCH/ens/common/wrflowinp_d0* . 2>/dev/null
cp $SCRATCH/ens/common/wrfinput_d0* .      # real.exe once; each member gets its own copy
cp $SCRATCH/ens/common/namelist.input $SCRATCH/ens/common/namelist.fire .
sed -n "$((SLURM_ARRAY_TASK_ID + 2))p" $SCRATCH/ens/ignitions.csv | \
  awk -F, '{print "lat,lon,time_s,radius_m\n"$0}' > ign.csv     # this member's ignition
python $HOME/bin/write_tign.py points wrfinput_d03 ign.csv --sr 5
srun ./wrf.exe

Cost decides the size: one member of the Forest Park setup is a full 3-domain WRF run, so tens of members are realistic where the prototype used thousands. A practical design: the 20–50 highest-risk starts from the ignition-danger map, under the 2–3 worst east-wind days.
