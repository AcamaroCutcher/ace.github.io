Installing WRF-SFIRE on an HPC cluster

Everything needed to build and run WRF-SFIRE on a Linux cluster, from the NetCDF libraries to the first test run and a Slurm job script.

What you are installing

A WRF-SFIRE simulation with real weather needs three things built with the same compiler and MPI: the libraries (NetCDF for all input and output, and GRIB2 support for the weather data), WRF-SFIRE itself (WRF with the fire model, from OpenWFM), and WPS, the preprocessor that builds the domains and interpolates weather and static data onto them. On a cluster you build once on a login node and run through the batch system.

First try the modules your cluster already has

Most HPC centres provide netcdf-c, netcdf-fortran, hdf5 and jasper as modules, often built per compiler and MPI. Run module avail netcdf. If NetCDF-C and NetCDF-Fortran are in different directories, either make a directory of symlinks with both include/ and lib/ contents and point $NETCDF at it, or use the Spack view below.

Step 1 · Libraries

Option A: build them yourself

This script builds everything into $HOME/wrf-libs, in dependency order. It takes 20–40 minutes; run it on a build or login node your centre allows compiling on.

build_libs.sh
#!/usr/bin/env bash
# build_libs.sh: zlib, HDF5, NetCDF-C, NetCDF-Fortran, libpng, JasPer into one prefix.
# Run on a login/build node with the compilers you will build WRF with (here GNU).
# Check each project's download page for newer releases; these URLs were checked in Nov 2026.
set -euo pipefail
export PREFIX=$HOME/wrf-libs                 # everything goes here
export CC=gcc CXX=g++ FC=gfortran F77=gfortran
export CPPFLAGS="-I$PREFIX/include" LDFLAGS="-L$PREFIX/lib"
export LD_LIBRARY_PATH=$PREFIX/lib:${LD_LIBRARY_PATH:-}
mkdir -p $PREFIX/src && cd $PREFIX/src
get() { [ -f "$(basename $1)" ] || curl -fLO "$1"; tar xzf "$(basename $1)"; }

get https://github.com/madler/zlib/releases/download/v1.3.1/zlib-1.3.1.tar.gz
(cd zlib-1.3.1 && ./configure --prefix=$PREFIX && make -j8 && make install)

get https://support.hdfgroup.org/ftp/HDF5/releases/hdf5-1.14/hdf5-1.14.3/src/hdf5-1.14.3.tar.gz
(cd hdf5-1.14.3 && ./configure --prefix=$PREFIX --with-zlib=$PREFIX --enable-hl --enable-fortran \
   && make -j8 && make install)

get https://downloads.unidata.ucar.edu/netcdf-c/4.9.2/netcdf-c-4.9.2.tar.gz
(cd netcdf-c-4.9.2 && ./configure --prefix=$PREFIX --enable-netcdf-4 --disable-dap --disable-byterange \
   && make -j8 && make install)

get https://downloads.unidata.ucar.edu/netcdf-fortran/4.6.1/netcdf-fortran-4.6.1.tar.gz
(cd netcdf-fortran-4.6.1 && LIBS="$(${PREFIX}/bin/nc-config --libs)" ./configure --prefix=$PREFIX \
   && make -j8 && make install)          # same prefix as NetCDF-C: WRF expects both in $NETCDF

get https://download.sourceforge.net/libpng/libpng-1.6.43.tar.gz
(cd libpng-1.6.43 && ./configure --prefix=$PREFIX && make -j8 && make install)

# JasPer 1.900.1 is the version the WRF compile tutorial uses for WPS's GRIB2 support
get https://www2.mmm.ucar.edu/wrf/OnLineTutorial/compile_tutorial/tar_files/jasper-1.900.1.tar.gz
(cd jasper-1.900.1 && ./configure --prefix=$PREFIX && make -j8 && make install)

$PREFIX/bin/nc-config --all | head -20
$PREFIX/bin/nf-config --all | head -20
echo "done: libraries in $PREFIX"

Option B: Spack

spack
# Alternative: let Spack build the libraries (and MPI) for you
git clone --depth=100 https://github.com/spack/spack.git ~/spack
. ~/spack/share/spack/setup-env.sh
spack compiler find
spack install netcdf-fortran ^netcdf-c+mpi ^hdf5+mpi+hl+fortran ^openmpi
spack install jasper libpng zlib
# WRF wants NetCDF-C and NetCDF-Fortran in ONE directory: make a view that merges them
spack view symlink ~/wrf-view netcdf-c netcdf-fortran hdf5 jasper libpng zlib
export NETCDF=~/wrf-view HDF5=~/wrf-view JASPERLIB=~/wrf-view/lib JASPERINC=~/wrf-view/include
spack load openmpi

The environment file

Source the same file before every build and inside every job script, so the run uses the libraries the build used.

~/wrf-env.sh
# wrf-env.sh: source this before building or running (". ~/wrf-env.sh")
module purge
module load gcc/13 openmpi/4.1            # names differ on every cluster: "module avail gcc openmpi"
export WRF_LIBS=$HOME/wrf-libs
export NETCDF=$WRF_LIBS                   # must contain include/netcdf.inc and lib/libnetcdff.*
export HDF5=$WRF_LIBS
export JASPERLIB=$WRF_LIBS/lib JASPERINC=$WRF_LIBS/include
export PATH=$WRF_LIBS/bin:$PATH
export LD_LIBRARY_PATH=$WRF_LIBS/lib:${LD_LIBRARY_PATH:-}
export WRFIO_NCD_LARGE_FILE_SUPPORT=1     # history files > 2 GB
ulimit -s unlimited                       # WRF needs a large stack

Step 2 · Build WRF-SFIRE

  1. Clone, configure and compile. em_fire builds the idealized fire cases (handy for a first test), em_real the real-data executables.

    build WRF-SFIRE
    . ~/wrf-env.sh
cd $HOME && git clone https://github.com/openwfm/WRF-SFIRE.git
cd WRF-SFIRE
git log -1 --oneline                      # record the version you build (e.g. the W4.4-S0.1 tag)
./configure
#   pick the "dmpar" line for your compiler, e.g.
#     34. (dmpar)  GNU (gfortran/gcc)        or   15. (dmpar)  INTEL (ifort/icc)
#   then nesting: 1 = basic
./compile -j 8 em_fire >& compile_em_fire.log    # idealized fire test cases (ideal.exe)
grep -i -E "error|abort" compile_em_fire.log | head
./clean                                     # keep configure.wrf, rebuild for real data
./compile -j 8 em_real >& compile_em_real.log    # real.exe, wrf.exe, ndown.exe
ls -l main/*.exe                            # wrf.exe and real.exe must be there

  2. A full build takes 20–60 minutes. If main/wrf.exe is missing, search the log from the top for the first error, not the last.

  3. The same executable runs SFIRE and the NCAR WRF-Fire code: ifire = 1 in namelist.input selects SFIRE and ifire = 2 the NCAR fire code (confirmed in dyn_em/module_first_rk_step_part1.F). Several options exist in only one of them (Section 06 and 08 list which).

Step 3 · Build WPS and get the static data

build WPS
. ~/wrf-env.sh
cd $HOME && git clone https://github.com/openwfm/WPS.git
cd WPS
export WRF_DIR=$HOME/WRF-SFIRE
./configure                                 # a "serial" option is fine for WPS, e.g. "Linux x86_64, gfortran (serial)"
./compile >& compile_wps.log
ls -l geogrid.exe ungrib.exe metgrid.exe    # all three must exist
# static geography (terrain, land use, ...): the standard WPS_GEOG data set, ~30 GB unpacked
#   https://www2.mmm.ucar.edu/wrf/users/download/get_sources_wps_geog.html
# OpenWFM also hosts a WPS_GEOG bundle with fire fuel/topography data:
#   wget https://demo.openwfm.org/web/wrfx/WPS_GEOG.tbz && tar xjf WPS_GEOG.tbz

For WRF-SFIRE, geogrid also writes the fire-mesh fields NFUEL_CAT (fuel category) and ZSF (terrain) at the refined resolution (entries with subgrid = yes in GEOGRID.TBL). This project ships its own Forest Park versions: the 30 m WUI fuel map and 10 m 3DEP terrain as geogrid tiles, plus a GEOGRID.TBL snippet and a namelist.wps for the three nested domains (Section 03; files in wrf/ and data/processed/geogrid_* of the project).

Step 4 · First test: the idealized hill

run the em_fire test
# smallest test: the idealized hill case (no WPS, no input data)
cd $HOME/WRF-SFIRE/test/em_fire
ls                                        # namelist.input, namelist.fire, input_sounding, ideal.exe, wrf.exe
grep -n "ibeh" namelist.fire              # ibeh = 2 (Balbi) in this file: set ibeh = 1 for Rothermel
./ideal.exe                               # writes wrfinput_d01
mpirun -np 4 ./wrf.exe                    # or srun inside a job, see below
tail -n 3 rsl.out.0000                    # must end with "SUCCESS COMPLETE WRF"
ncdump -h wrfout_d01_* | grep -E "LFN|TIGN_G|FGRNHFX|FXLONG"

If this works, the compiler, MPI and NetCDF are all good. Sections 08–11 then set up real Forest Park runs.

Step 5 · Running through the batch system

Never run wrf.exe on a login node. A Slurm script for the real case:

run_wrf.slurm
#!/bin/bash
#SBATCH --job-name=sfire-forestpark
#SBATCH --nodes=2
#SBATCH --ntasks-per-node=64              # cores per node on your cluster
#SBATCH --time=08:00:00
#SBATCH --partition=compute               # ask your admins
#SBATCH --output=sfire_%j.log
. ~/wrf-env.sh
cd $SLURM_SUBMIT_DIR                       # the run directory (see Section 08)
srun ./real.exe                            # or run real.exe in a separate, smaller job
grep -q "SUCCESS COMPLETE REAL" rsl.error.0000 || { echo "real.exe failed"; exit 1; }
mv rsl.out.0000 rsl.real.out.0000
srun ./wrf.exe
tail -n 2 rsl.error.0000

Submit with sbatch run_wrf.slurm, follow with squeue -u $USER and tail -f rsl.error.0000. On PBS systems:

run_wrf.pbs
#!/bin/bash
#PBS -N sfire-forestpark
#PBS -l select=2:ncpus=36:mpiprocs=36
#PBS -l walltime=08:00:00
#PBS -j oe
. ~/wrf-env.sh
cd $PBS_O_WORKDIR
mpiexec ./wrf.exe
  • How many cores? WRF splits each domain into patches; each MPI rank needs at least ~10 × 10 atmospheric cells on the smallest domain it computes. For the Forest Park nests (d03 is 108 × 108 cells) that means up to about 100 ranks are useful. Measure: run 10 simulated minutes with 32, 64 and 128 ranks and compare the "Timing for main" lines in rsl.error.0000.
  • Storage. A 9-hour run with 15-minute history on d03 and the fire mesh writes several GB. Run in $SCRATCH, not $HOME.
  • Logs. Every rank writes rsl.out.NNNN and rsl.error.NNNN; rank 0 has the summary. Fire messages (ignitions, burned area, max spread rate) appear there when fire_print_msg ≥ 1.

Common build and run errors

SymptomLikely cause and fix
configure says NetCDF not found, or netcdf.inc missing$NETCDF must hold both C and Fortran libraries: ls $NETCDF/include/netcdf.inc $NETCDF/lib/libnetcdff*.
Undefined references to nf_ or H5 symbolsLibraries built with a different compiler, or HDF5 missing from the link. Rebuild the libraries with the same compilers; check nf-config --flibs.
gfortran 10+: Rank mismatch / Type mismatch errors (mostly in WPS)Add -fallow-argument-mismatch to the Fortran flags (FFLAGS/F77FLAGS) in configure.wps (recent WRF configure scripts add it themselves).
Preprocessor errors on comment linesFrom the OpenWFM wiki: run ./clean -a, ./configure, add -nostdinc to the CPP line in configure.wrf (or configure.wps), recompile.
ungrib.exe not builtJasPer/libpng/zlib not found: set JASPERLIB/JASPERINC before ./configure in WPS.
Segmentation fault at start of wrf.exeStack too small: ulimit -s unlimited in the job script; also try fewer ranks for a small domain.
“fire mesh refinement ratio must be positive”sr_x/sr_y must be > 0 on the domain with ifire ≠ 0.
“fire_upwinding value not supported, 3 recommended”With ifire = 1 only values 0–4 (and 9, mapped to 3) are allowed.
“fmoist_run=T requires fire_fmc_read=0”Set fire_fmc_read = 0 when the moisture model is on.
CFL errors / NaNs after the fire startsAtmospheric time step too long for d03, or very steep terrain: shorten time_step, keep w_damping = 1, smooth the terrain.
