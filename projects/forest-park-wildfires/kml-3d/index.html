From wrfout to KML, KMZ, GeoJSON and textures

Three details of WRF-SFIRE output the script handles
  • Padding. Fire-mesh arrays have sr extra cells at the far edges that are not part of the domain (zeros in FXLONG/FXLAT); they are cropped.
  • TIGN_G is only valid where LFN ≤ 0. Unburned cells keep a placeholder time near the start of the run (init_no_fire), so TIGN_G ≤ t alone marks the whole domain burned. Perimeters come from LFN = 0 instead, as in wrfxpy.
  • Projection. The fire mesh is on WRF's Lambert grid. KML image overlays need a lat/lon box, so rasters are resampled first.

Google Earth, QGIS and CesiumJS

  • Google Earth (desktop or web): open perimeters.kmz and fire_heat.kmz; the time slider appears because every feature has a TimeSpan. Tilt the view to see the fire on the 3-D terrain of the West Hills.
  • QGIS: drag in perimeters.geojson, then Layer Properties → Temporal → "Single field with date/time" = time, and play it with the Temporal Controller; export frames to make a video.
  • CesiumJS gives the same thing on a web page, with world terrain and the KML clock driving the animation:
cesium.js
// CesiumJS (browser 3-D globe with terrain): load the time-stamped KMZ and play it
const viewer = new Cesium.Viewer("cesium", { terrain: Cesium.Terrain.fromWorldTerrain() });
const ds = await Cesium.KmlDataSource.load("perimeters.kmz",
  { camera: viewer.scene.camera, canvas: viewer.scene.canvas, clampToGround: true });
viewer.dataSources.add(ds);
viewer.clock.shouldAnimate = true;            // KML TimeSpans drive Cesium's clock and timeline
viewer.clock.multiplier = 600;                // 10 simulated minutes per second
viewer.flyTo(ds);

Toward a realistic animation

Perimeters every 15 minutes look like contour maps. A realistic animation needs three things the model already has:

  1. Continuous time. The arrival time \(T(\mathbf x)\) is known everywhere on the 30 m mesh, so the front can be drawn at any instant by comparing \(T\) with the current time in a shader, with no interpolation between frames. (The fire maps on this site's hub and fuel-map pages are drawn exactly this way.)
  2. Burn-out. Behind the front the fuel burns as \(e^{-(t-T)/T_f}\) with \(T_f\) from 8 s (grass) to 18 min (timber), which sets how long each place glows and smokes.
  3. Smoke and wind in 3-D. The smoke tracer and the 3-D wind from the atmosphere turn into volumes and particle forces.
the shader logic, for any engine
Shader Graph (Unity) or a material node tree (Blender, Unreal) - the same logic:
  a      = sample(arrival_time.png) * 65535            // counts; 0 = never burns   (import as R16, linear, no compression)
  now    = _SimTimeCounts
  age    = (now - a) * secondsPerCount                  // seconds since the fire arrived
  burned = (a > 0) && (age > 0)
  front  = burned * (1 - smoothstep(0, 120, age))       // glowing band: first 2 minutes
  ember  = burned * exp(-age / 900)                     // smouldering for ~15 min (timber T_f is ~18 min)
  albedo = lerp(fuelColour, charColour, burned)
  emission = front * flameColour * 40 + ember * emberColour * 4
Use the same age to spawn particles: VFX Graph / Niagara "sample texture" at random points, keep those with 0 < age < 120 s.

Unity

  1. Terrain. Either Cesium for Unity (streams real-world terrain and imagery; place the fire with a georeference at the bounding box in textures.json), or a plain Unity Terrain: resample terrain.png to a square heightmap of 513, 1025 or 2049 pixels, save as 16-bit RAW, import it in Terrain Settings, and set the terrain size to the box size and the height to the relief in textures.json.

  2. Fire texture. Import arrival_time.png with sRGB off, compression None, filter Point, format R16.

  3. Shader Graph. Build the logic above (Sample Texture 2D → Subtract → Smoothstep → Emission), with a float property _SimTimeCounts.

  4. Clock. Attach this script and drag in the material:

    FireClock.cs
    // FireClock.cs: drives the fire shader from the arrival-time texture (Unity, URP/HDRP)
using UnityEngine;
public class FireClock : MonoBehaviour {
    public Material terrainMaterial;          // uses the shader graph described below
    public float secondsPerCount = 1.0f;      // arrival_seconds_per_count from textures.json
    public float simSecondsPerRealSecond = 600f;
    public float simTime;                     // seconds since the WRF run started
    void Update() {
        simTime += Time.deltaTime * simSecondsPerRealSecond;
        // the shader compares arrival (in counts) with the current time (in counts)
        terrainMaterial.SetFloat("_SimTimeCounts", 1f + simTime / secondsPerCount);
    }
}

  5. Flames and smoke. A VFX Graph that samples the arrival texture at random positions and spawns flame particles where 0 < age < 120 s and smoke where age < 15 min; drive the smoke with a 3-D vector field exported from the WRF wind (U, V, W) at a few heights.

  6. Film it. Timeline + Cinemachine for the camera, the Recorder package for frames or MP4.

Blender

Blender gives the most realistic stills and flyovers (Cycles path tracing, volumetric smoke). The script builds the terrain from terrain.png and an emission material whose fire front is driven by a keyframed clock:

blender_fire.py
# blender_fire.py: terrain + animated fire material from the converter's textures.
# Run inside Blender (Scripting tab, or: blender --python blender_fire.py). Written for Blender 4.x.
import bpy, json, os
D = "/path/to/fire_viz"                            # output folder of wrfsfire_to_kml.py
meta = json.load(open(os.path.join(D, "textures.json")))
size_x = meta["width"] * meta["pixel_m"]; size_y = meta["height"] * meta["pixel_m"]
relief = meta["terrain_max_m"] - meta["terrain_min_m"]

bpy.ops.mesh.primitive_grid_add(x_subdivisions=meta["width"] // 2, y_subdivisions=meta["height"] // 2, size=1)
ob = bpy.context.active_object; ob.scale = (size_x, size_y, 1)
img_z = bpy.data.images.load(os.path.join(D, "terrain.png")); img_z.colorspace_settings.name = "Non-Color"
tex = bpy.data.textures.new("terrain", "IMAGE"); tex.image = img_z; tex.extension = "EXTEND"
mod = ob.modifiers.new("relief", "DISPLACE"); mod.texture = tex; mod.texture_coords = "UV"
mod.strength = relief; mod.mid_level = 0.0

mat = bpy.data.materials.new("fire"); mat.use_nodes = True; ob.data.materials.append(mat)
nt = mat.node_tree; N = nt.nodes; L = nt.links
arr = N.new("ShaderNodeTexImage"); arr.image = bpy.data.images.load(os.path.join(D, "arrival_time.png"))
arr.image.colorspace_settings.name = "Non-Color"; arr.interpolation = "Closest"
now = N.new("ShaderNodeValue"); now.label = "sim time (counts / 65535)"
age = N.new("ShaderNodeMath"); age.operation = "SUBTRACT"          # now - arrival
L.new(now.outputs[0], age.inputs[0]); L.new(arr.outputs["Color"], age.inputs[1])
front = N.new("ShaderNodeMapRange")                                # 1 just after arrival, 0 after ~2 min
front.inputs["From Min"].default_value = 0.0
front.inputs["From Max"].default_value = 120.0 / (meta["arrival_seconds_per_count"] * 65535)
front.inputs["To Min"].default_value = 1.0; front.inputs["To Max"].default_value = 0.0
L.new(age.outputs[0], front.inputs["Value"])
bsdf = N["Principled BSDF"]
L.new(front.outputs["Result"], bsdf.inputs["Emission Strength"])
bsdf.inputs["Emission Color"].default_value = (1.0, 0.35, 0.05, 1)
# animate the clock: frame 1 = run start, 250 frames = whole run
fc = now.outputs[0]; fc.default_value = 0.0; fc.keyframe_insert("default_value", frame=1)
fc.default_value = 1.0; fc.keyframe_insert("default_value", frame=250)
# (cells that never burn have arrival 0, so mask them: add a Greater Than on arrival > 0 and multiply)
  • Real terrain and imagery: the BlenderGIS add-on imports DEMs (for example this project's 10 m 3DEP GeoTIFF) and basemaps in the right place.
  • Smoke: either Mantaflow (a smoke domain over the fire with the burning area as an emitter whose density follows the front mask), or, closer to the model, WRF's own smoke tracer as OpenVDB volumes, imported with Add → Volume → Import OpenVDB, one per frame:
wrf_smoke_to_vdb.py
# 3-D smoke for Blender/Houdini/Unreal: one OpenVDB volume per output time from WRF's smoke tracer.
# Needs the OpenVDB Python bindings (e.g. "pip install openvdb" where available, or Blender's bundled module).
from netCDF4 import Dataset
import numpy as np, openvdb as vdb
d = Dataset("wrfout_d03_2020-09-08_00:00:00")
for k in range(len(d["Times"])):
    smoke = np.asarray(d["fire_smoke"][k], dtype="float32")      # (bottom_top, south_north, west_east), g/kg
    grid = vdb.FloatGrid(); grid.copyFromArray(np.transpose(smoke, (2, 1, 0)))   # x, y, z order
    grid.name = "density"; grid.transform = vdb.createLinearTransform(voxelSize=150.0)
    vdb.write(f"smoke_{k:03d}.vdb", grids=[grid])
# Note: model levels are not equally spaced in height; resample to a regular z grid (from PH/PHB) for accuracy.

Unreal Engine, VAPOR and ParaView

  • Unreal Engine: Cesium for Unreal for the globe and terrain, a material with the same arrival-time logic, Niagara for flames and embers, and the VDB smoke through Unreal's Sparse Volume Textures. Movie Render Queue for the film.
  • VAPOR (NCAR, free): reads WRF-ARW output directly, including the terrain-following grid, and renders the smoke tracer, temperature and wind in 3-D: the fastest way to see the plume the coupled model produced. Fire-mesh fields are not on the atmospheric grid, so overlay the perimeters as an image or use the atmospheric AVG_FUEL_FRAC / heat-flux fields.
  • ParaView: open the NetCDF with the CF reader, or convert to VTK with Python; good for slices and isosurfaces of vertical velocity above the fire.
What was tested

The converter was run end to end on the synthetic file: the KML parses with 608 time-stamped polygons, the KMZ holds 13 overlays plus a colour bar with matching paths (a path bug was found and fixed this way), and the perimeters and texture land on Forest Park with north up. The Unity, Blender, Cesium and VDB snippets were written against those programs' documented APIs but not run here.
