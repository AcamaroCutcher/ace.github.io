Virtual functions and dynamic dispatch

Marking a function virtual moves the decision of which version runs from compile time to run time: the actual object decides. That one keyword is what makes object-oriented C++ work.

virtual and override

Marking a member function virtual tells the compiler: "decide which version to call when the program runs, from the actual object". Derived classes then override it, and the keyword override asks the compiler to check that they really do.

virtual.cppRun online ↗
// virtual.cpp -- virtual functions: the call is decided by the object, not by the pointer type
#include <iostream>
#include <memory>
#include <string>
#include <vector>

class Shape {
public:
    explicit Shape(std::string name) : name_(std::move(name)) {}
    virtual ~Shape() = default;                     // any class with virtual functions needs this
    std::string name() const { return name_; }
    virtual double area() const { return 0.0; }     // virtual: derived classes may override
private:
    std::string name_;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : Shape("circle"), r_(r) {}
    double area() const override { return 3.141592653589793 * r_ * r_; }   // override: checked by the compiler
private:
    double r_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : Shape("rectangle"), w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
private:
    double w_, h_;
};

void report(const Shape& s) { std::cout << "report: " << s.name() << " has area " << s.area() << '\n'; }

int main() {
    Circle c(2);
    report(c);                                      // now Circle::area runs

    std::vector<std::unique_ptr<Shape>> shapes;     // one container, many concrete types
    shapes.push_back(std::make_unique<Circle>(1));
    shapes.push_back(std::make_unique<Rectangle>(2, 3));
    shapes.push_back(std::make_unique<Shape>("blob"));
    double total = 0;
    for (const auto& s : shapes) {
        std::cout << "  " << s->name() << ": " << s->area() << '\n';
        total += s->area();
    }
    std::cout << "total area " << total << '\n';

    Shape copy = c;                                 // slicing: only the Shape part is copied
    std::cout << "sliced copy: " << copy.name() << " has area " << copy.area() << '\n';
}
Output
report: circle has area 12.5664
  circle: 3.14159
  rectangle: 6
  blob: 0
total area 9.14159
sliced copy: circle has area 0

Step through it

Step into report(c) and then into s.area(): the call made through a const Shape& lands in Circle::area. Expand s to see that it really refers to a Circle. The recording was made by stepping through the real program under LLDB; use the buttons, the slider or the arrow keys.

Now report(c) prints the circle's area, and one loop over std::vector<std::unique_ptr<Shape>> handles every kind of shape. That is polymorphism. The last line shows slicing: copying a Circle into a Shape variable copies only the Shape part, so the copy really is a plain Shape. Polymorphism works through references and pointers, never through copies.

How it works: the vtable

Each class with virtual functions gets a virtual table: an array of pointers to its versions of the virtual functions. Each object stores a hidden pointer to its class's table (the vptr, the 8 bytes measured in lesson 04, which GDB shows as _vptr.Shape). A virtual call loads the vptr, picks the right slot, and jumps. Making overriding safe

Always write override Without it, a typo or a missing const silently creates a new, unrelated function. With it, the compiler catches the mistake. (Mission 2 in the debugger lesson is exactly this bug, found the hard way.)
override_typo.cpp
struct Animal { virtual ~Animal() = default; virtual const char* sound() const { return "..."; } };
struct Cat : Animal { const char* Sound() const override { return "meow"; } };
int main() { Cat c; }
Compiler says
override_typo.cpp:2:49: error: only virtual member functions can be marked 'override'

What counts as an override?

Pick a way to write area in Circle. The program prints what a call through const Shape& reaches.

Virtual destructor A class meant to be used through base pointers needs virtual ~Base() (or virtual ~Base() = default;). Otherwise delete through a Base*, including the one inside std::unique_ptr<Base>, is undefined behavior; in practice the derived destructor is skipped, as the widget in lesson 02 showed.

final stops further overriding of one function (void f() override final;) or derivation from a whole class (class Square final). Besides documenting intent, it lets the compiler call a final function directly instead of through the vtable.

Key points

  • Virtual calls are resolved from the object's dynamic type, but only through pointers and references.
  • Write override on every override and a virtual destructor in every polymorphic base.
  • Never pass polymorphic objects by value: that slices them.
