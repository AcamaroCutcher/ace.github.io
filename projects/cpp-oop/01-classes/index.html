Classes and encapsulation

A class bundles data with the operations allowed on it. The point is not tidiness: it is that the class can guarantee its data always makes sense.

Invariants: what a class guarantees

A class groups data members with member functions. The key idea is the invariant: a fact that is true for every object of the class at all times. For a rectangle, "both sides are positive". The constructor establishes the invariant, every public member function preserves it, and making the data private means no other code can break it.

classes.cppRun online ↗
// classes.cpp -- a class bundles data with the functions that keep it valid
#include <iostream>
#include <stdexcept>

class Rectangle {
public:                                   // the interface: what users of the class may call
    Rectangle(double w, double h) : width_(w), height_(h) {   // constructor with a member initializer list
        if (w <= 0 || h <= 0) throw std::invalid_argument("sides must be positive");
        ++count_;
    }
    double area() const { return width_ * height_; }          // const: promises not to change the object
    double perimeter() const { return 2 * (width_ + height_); }
    void scale(double f) {
        if (f <= 0) throw std::invalid_argument("scale factor must be positive");
        width_ *= f;
        height_ *= f;
    }
    double width() const { return width_; }                   // read access without write access
    static int count() { return count_; }                     // static: belongs to the class, not an object

private:                                  // the implementation: only member functions can touch it
    double width_, height_;
    static inline int count_ = 0;         // C++17 inline static member
};

int main() {
    Rectangle r(3, 4);
    std::cout << "area " << r.area() << ", perimeter " << r.perimeter() << '\n';
    r.scale(2);
    std::cout << "after scale(2): width " << r.width() << ", area " << r.area() << '\n';
    // r.width_ = -1;          // error: 'width_' is a private member of 'Rectangle'

    try {
        Rectangle bad(-1, 2);  // the constructor refuses to build an invalid object
    } catch (const std::invalid_argument& e) {
        std::cout << "rejected: " << e.what() << '\n';
    }

    const Rectangle sq(5, 5);
    std::cout << "square area " << sq.area() << '\n';   // fine: area() is const
    // sq.scale(2);            // error: scale() is not const, sq is
    std::cout << "rectangles built: " << Rectangle::count() << '\n';
}
Output
area 12, perimeter 14
after scale(2): width 6, area 48
rejected: sides must be positive
square area 25
rectangles built: 2

  • public / private: anyone can call the public part; only the class's own member functions can touch the private part. A struct is the same as a class except that its members are public by default; by convention, struct is used for plain data with no invariant.
  • Member initializer list, : width_(w), height_(h), initializes members before the constructor body runs. Members are always initialized in the order they are declared, whatever order the list uses.
  • const member functions promise not to modify the object, so they can be called on const objects and through const&. Mark every member function that does not change the object const; forgetting it is one of the most common reasons code "will not compile" later.
  • static members belong to the class as a whole: there is one count_, not one per object.
  • A constructor that cannot establish the invariant should throw: then no invalid object ever exists.

Operator overloading: value classes that read like math

For small mathematical types, overloaded operators let code look like the formula it implements. The usual recipe: compound operators (+=, *=) are members that modify *this; binary operators (+, *) are non-members written in terms of them, so both operands are treated alike and 2.0 * v works as well as v * 2.0; operator<< for printing must be a non-member because its left operand is the stream.

// operators.cpp -- operator overloading makes a small value class read like math
#include <cmath>
#include <iostream>

class Vec2 {
public:
    constexpr Vec2(double x = 0, double y = 0) : x_(x), y_(y) {}
    double x() const { return x_; }
    double y() const { return y_; }
    double norm() const { return std::hypot(x_, y_); }

    Vec2& operator+=(const Vec2& o) { x_ += o.x_; y_ += o.y_; return *this; }   // compound: a member, returns *this
    Vec2& operator*=(double k) { x_ *= k; y_ *= k; return *this; }
    Vec2 operator-() const { return {-x_, -y_}; }                             // unary minus

    friend bool operator==(const Vec2& a, const Vec2& b) { return a.x_ == b.x_ && a.y_ == b.y_; }
    friend std::ostream& operator<<(std::ostream& out, const Vec2& v) {        // printing: must be a non-member
        return out << '(' << v.x_ << ", " << v.y_ << ')';
    }
private:
    double x_, y_;
};

// binary operators as non-members, written with the compound ones: both operands are treated alike
inline Vec2 operator+(Vec2 a, const Vec2& b) { return a += b; }
inline Vec2 operator-(Vec2 a, const Vec2& b) { return a += -b; }
inline Vec2 operator*(Vec2 v, double k) { return v *= k; }
inline Vec2 operator*(double k, Vec2 v) { return v *= k; }    // so that 2.0 * v works too
inline double dot(const Vec2& a, const Vec2& b) { return a.x() * b.x() + a.y() * b.y(); }

int main() {
    Vec2 p(1, 2), v(0.5, -1);
    double dt = 0.1;
    for (int step = 0; step < 3; ++step) {
        p += v * dt;                       // reads like the physics: p <- p + v dt
        std::cout << "step " << step + 1 << ": p = " << p << '\n';
    }
    Vec2 a(3, 4);
    std::cout << "|a| = " << a.norm() << ", 2*a = " << 2.0 * a << ", -a = " << -a << '\n';
    std::cout << "a.b = " << dot(a, Vec2(1, 1)) << ", a == (3,4)? " << std::boolalpha << (a == Vec2(3, 4)) << '\n';
}
Output
step 1: p = (1.05, 1.9)
step 2: p = (1.1, 1.8)
step 3: p = (1.15, 1.7)
|a| = 5, 2*a = (6, 8), -a = (-3, -4)
a.b = 7, a == (3,4)? true

When to overload Overload an operator only when its meaning is obvious to every reader: arithmetic for vectors and matrices, == for values, << for printing, () for indexing a grid. Do not overload &&, || or the comma operator, and do not give + side effects. In C++20, operator<=> ("spaceship") can generate all six comparisons at once.

Key points

  • Design a class around its invariant; keep the data private and the interface small.
  • Use the initializer list; mark non-modifying member functions const.
  • Value types (vectors, complex numbers, intervals) benefit from operators; most other classes do not need any.
