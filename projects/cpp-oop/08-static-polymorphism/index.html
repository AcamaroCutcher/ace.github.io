Beyond virtual: templates, CRTP, variant and concepts

Virtual functions are one way to make one piece of code work with many types. C++ has others that decide at compile time, and choosing well depends on whether the set of types is open or closed.

Templates: polymorphism at compile time

A function template works with any type that has the operations it uses. The compiler writes a separate version for each type, so calls are direct and usually inlined, and the types need no common base class. The price: the type must be known at compile time, so a single container cannot hold a mix.

templates.cppRun online ↗
// templates.cpp -- static polymorphism: the type is fixed at compile time, no vtable needed
#include <iostream>
#include <vector>

struct Circle { double r; double area() const { return 3.14159 * r * r; } };   // no common base class
struct Rect   { double w, h; double area() const { return w * h; } };

template <typename T>                       // works for any T with an area() member
double total_area(const std::vector<T>& shapes) {
    double t = 0;
    for (const T& s : shapes) t += s.area();    // resolved at compile time and usually inlined
    return t;
}

template <typename... Ts>                   // a variadic template: any number of arguments of any types
double sum_areas(const Ts&... shapes) { return (shapes.area() + ... + 0.0); }   // C++17 fold expression

int main() {
    std::vector<Circle> circles = {{1}, {2}};
    std::vector<Rect> rects = {{2, 3}, {1, 1}};
    std::cout << "circles " << total_area(circles) << ", rects " << total_area(rects) << '\n';
    std::cout << "mixed, fixed at compile time: " << sum_areas(Circle{1}, Rect{2, 3}, Rect{1, 1}) << '\n';
    // total_area(std::vector<int>{1, 2});   // error: 'int' has no member 'area' -- found at compile time
}
Output
circles 15.708, rects 7
mixed, fixed at compile time: 10.1416

CRTP: shared code in a base, without virtual

In the Curiously Recurring Template Pattern, a class derives from a base template instantiated with itself. The base can then call the derived class's functions through a static_cast, resolved at compile time. It gives code reuse like a base class, with no vptr and no run-time dispatch.

crtp.cppRun online ↗
// crtp.cpp -- the Curiously Recurring Template Pattern: shared code in a base, no virtual calls
#include <iostream>

template <typename Derived>
class Shape {                                   // the base knows its derived type as a template parameter
public:
    void describe() const {
        const auto& self = static_cast<const Derived&>(*this);   // safe: Derived really derives from Shape<Derived>
        std::cout << self.name() << ": area " << self.area() << ", twice " << 2 * self.area() << '\n';
    }
};

class Circle : public Shape<Circle> {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const { return 3.14159 * r_ * r_; }
    const char* name() const { return "circle"; }
private:
    double r_;
};

class Square : public Shape<Square> {
public:
    explicit Square(double s) : s_(s) {}
    double area() const { return s_ * s_; }
    const char* name() const { return "square"; }
private:
    double s_;
};

template <typename D>
void show(const Shape<D>& s) { s.describe(); }  // generic, but every call is resolved at compile time

int main() {
    show(Circle(1));
    show(Square(3));
    // Circle and Square share no common type: you cannot put both in one std::vector<Shape<?>>.
}
Output
circle: area 3.14159, twice 6.28318
square: area 9, twice 18

std::variant: a closed set of types

When the set of types is fixed and known (circle, rectangle, triangle and nothing else), std::variant holds exactly one of them by value, with no heap allocation and no inheritance. std::visit runs the right lambda, and the compiler checks that every alternative is handled:

variant.cppRun online ↗
// variant.cpp -- a closed set of types without inheritance: std::variant and std::visit
#include <cmath>
#include <iostream>
#include <string>
#include <variant>
#include <vector>

struct Circle { double r; };
struct Rect { double w, h; };
struct Triangle { double a, b, c; };
using Shape = std::variant<Circle, Rect, Triangle>;     // a Shape is exactly one of these

template <class... Fs> struct overloaded : Fs... { using Fs::operator()...; };   // one lambda per type
template <class... Fs> overloaded(Fs...) -> overloaded<Fs...>;

double area(const Shape& s) {
    return std::visit(overloaded{
        [](const Circle& c) { return 3.14159 * c.r * c.r; },
        [](const Rect& r) { return r.w * r.h; },
        [](const Triangle& t) { double p = (t.a + t.b + t.c) / 2; return std::sqrt(p * (p - t.a) * (p - t.b) * (p - t.c)); },
    }, s);                                              // forget a type and this does not compile
}

std::string name(const Shape& s) {
    return std::visit(overloaded{
        [](const Circle&) { return std::string("circle"); },
        [](const Rect&) { return std::string("rect"); },
        [](const Triangle&) { return std::string("triangle"); },
    }, s);
}

int main() {
    std::vector<Shape> shapes = {Circle{1}, Rect{2, 3}, Triangle{3, 4, 5}};   // values, not pointers
    for (const auto& s : shapes) std::cout << name(s) << ": " << area(s) << '\n';
    std::cout << "sizeof(Shape) = " << sizeof(Shape) << " bytes (the largest alternative + a tag)\n";
}
Output
circle: 3.14159
rect: 6
triangle: 6
sizeof(Shape) = 32 bytes (the largest alternative + a tag)

Inheritance and variants are mirror images. With virtual functions it is easy to add a type (one new class) and hard to add an operation (edit every class). With a variant it is easy to add an operation (one new visit) and hard to add a type (edit every visitor). Lesson 09's Visitor pattern brings the variant's trade-off to class hierarchies.

C++20 concepts: naming the requirements

A template's requirements on its type used to be implicit, and violating them produced long errors from deep inside the template. A concept states them up front, like an interface checked at compile time:

concepts.cppRun online ↗
// concepts.cpp -- C++20 concepts: name the requirements a template places on its type
// build: -std=c++20
#include <concepts>
#include <iostream>
#include <vector>

template <typename T>
concept HasArea = requires(const T& s) {
    { s.area() } -> std::convertible_to<double>;    // T must have area() returning something like a double
};

struct Circle { double r; double area() const { return 3.14159 * r * r; } };
struct Rect { double w, h; double area() const { return w * h; } };
struct Label { const char* text; };                 // no area()

template <HasArea T>
double total_area(const std::vector<T>& v) {
    double t = 0;
    for (const auto& s : v) t += s.area();
    return t;
}

int main() {
    std::cout << total_area(std::vector<Circle>{{1}, {1}}) << '\n';
    std::cout << total_area(std::vector<Rect>{{2, 3}}) << '\n';
    std::cout << std::boolalpha << "Label has an area? " << HasArea<Label> << '\n';
    // total_area(std::vector<Label>{{"x"}});   // error: constraints not satisfied: 'HasArea<Label>'
}
Output
6.28318

Label has an area? false

What does each cost? Measured

A million shapes, half circles and half rectangles in random order, summing their areas. Each loop is timed 15 times and the best time kept:

bench.cppRun online ↗
// bench.cpp -- the cost of each kind of polymorphism, measured
// build: -O2
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <memory>
#include <random>
#include <type_traits>
#include <variant>
#include <vector>

struct Shape { virtual ~Shape() = default; virtual double area() const = 0; };
struct Circle : Shape { double r; explicit Circle(double r) : r(r) {} double area() const override { return 3.14159 * r * r; } };
struct Rect : Shape { double w, h; Rect(double w, double h) : w(w), h(h) {} double area() const override { return w * h; } };

struct VC { double r; };
struct VR { double w, h; };
using VShape = std::variant<VC, VR>;

template <class F> double best_ns(F f, int n) {    // best of 15 runs, in nanoseconds per shape
    double best = 1e30;
    for (int rep = 0; rep < 15; ++rep) {
        auto t0 = std::chrono::steady_clock::now();
        volatile double sink = f();
        (void)sink;
        auto t1 = std::chrono::steady_clock::now();
        best = std::min(best, std::chrono::duration<double, std::nano>(t1 - t0).count() / n);
    }
    return best;
}

int main() {
    const int n = 1000000;
    std::mt19937 rng(42);
    std::uniform_real_distribution<double> u(0.5, 2.0);
    std::vector<std::unique_ptr<Shape>> virt;
    std::vector<VShape> var;
    std::vector<VC> circles; std::vector<VR> rects;
    for (int i = 0; i < n; ++i) {
        double a = u(rng), b = u(rng);
        if (rng() % 2) { virt.push_back(std::make_unique<Circle>(a)); var.push_back(VC{a}); circles.push_back(VC{a}); }
        else { virt.push_back(std::make_unique<Rect>(a, b)); var.push_back(VR{a, b}); rects.push_back(VR{a, b}); }
    }
    double t_virt = best_ns([&] { double t = 0; for (auto& s : virt) t += s->area(); return t; }, n);
    double t_var = best_ns([&] {
        double t = 0;
        for (auto& s : var)
            t += std::visit([](const auto& x) {
                if constexpr (std::is_same_v<std::decay_t<decltype(x)>, VC>) return 3.14159 * x.r * x.r;
                else return x.w * x.h;
            }, s);
        return t;
    }, n);
    double t_split = best_ns([&] {
        double t = 0;
        for (auto& c : circles) t += 3.14159 * c.r * c.r;
        for (auto& r : rects) t += r.w * r.h;
        return t;
    }, n);
    std::printf("%-44s %6.2f ns per shape\n", "virtual calls, vector<unique_ptr<Shape>>", t_virt);
    std::printf("%-44s %6.2f ns per shape\n", "std::visit, vector<variant<...>>", t_var);
    std::printf("%-44s %6.2f ns per shape\n", "one vector per type, no dispatch at all", t_split);
}
Output
virtual calls, vector<unique_ptr<Shape>>       3.49 ns per shape
std::visit, vector<variant<...>>               3.64 ns per shape
one vector per type, no dispatch at all        0.64 ns per shape

Download bench.cpp compiled with -std=c++17 -Wall -Wextra -O2

On this machine a virtual call and a std::visit cost about the same, a few nanoseconds per shape, while sorting shapes by type into separate arrays and skipping dispatch altogether is several times faster: each loop then does one simple thing, which the compiler can optimize aggressively. Your numbers will differ with the processor and compiler, but the lesson holds: dispatch per element costs little for most code and matters only in the innermost loops of numerical work. Measure before optimizing.

Key points

  • Open set of types decided at run time: virtual functions. Closed set: std::variant. Known at compile time: templates.
  • Constrain templates with concepts for clear errors.
  • The cost of dispatch is small; data layout usually matters more.
