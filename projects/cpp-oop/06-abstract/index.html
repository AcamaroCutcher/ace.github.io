Abstract classes and interfaces

An abstract class states what every derived class must do without saying how. It cannot be instantiated; it exists to be a contract that code can rely on.

Pure virtual functions

Returning 0 from Shape::area() was a lie: there is no sensible area for "a shape in general". A pure virtual function, written = 0, has no implementation in the base class, and a class with at least one pure virtual function is an abstract class:

  • you cannot create objects of an abstract class;
  • you can have pointers and references to it, and that is how it is used;
  • a derived class becomes concrete once every pure virtual function has been overridden, by itself or by a class between it and the base.
abstract.cppRun online ↗
// abstract.cpp -- an abstract base class states what every shape must provide
#include <algorithm>
#include <cmath>
#include <iostream>
#include <memory>
#include <string>
#include <vector>

constexpr double pi = 3.141592653589793;

class Shape {                                       // abstract: it has pure virtual functions
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;                // "= 0": no implementation here; derived classes must provide one
    virtual double perimeter() const = 0;
    virtual std::string name() const = 0;

    void describe() const {                         // ordinary function built on the pure virtual ones
        std::cout << name() << ": area " << area() << ", perimeter " << perimeter() << '\n';
    }
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return pi * r_ * r_; }
    double perimeter() const override { return 2 * pi * r_; }
    std::string name() const override { return "circle"; }
private:
    double r_;
};

class Rectangle : public Shape {
public:
    Rectangle(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
    double perimeter() const override { return 2 * (w_ + h_); }
    std::string name() const override { return "rectangle"; }
protected:
    double w_, h_;
};

class Square final : public Rectangle {             // final: nothing may derive from Square
public:
    explicit Square(double s) : Rectangle(s, s) {}
    std::string name() const override { return "square"; }   // reuses Rectangle's area and perimeter
};

class Triangle : public Shape {
public:
    Triangle(double a, double b, double c) : a_(a), b_(b), c_(c) {}
    double area() const override {                  // Heron's formula
        double s = perimeter() / 2;
        return std::sqrt(s * (s - a_) * (s - b_) * (s - c_));
    }
    double perimeter() const override { return a_ + b_ + c_; }
    std::string name() const override { return "triangle"; }
private:
    double a_, b_, c_;
};

int main() {
    // Shape s;                                     // error: variable type 'Shape' is an abstract class
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(1));
    shapes.push_back(std::make_unique<Rectangle>(2, 3));
    shapes.push_back(std::make_unique<Square>(2));
    shapes.push_back(std::make_unique<Triangle>(3, 4, 5));

    for (const auto& s : shapes) s->describe();

    std::sort(shapes.begin(), shapes.end(),
              [](const auto& a, const auto& b) { return a->area() < b->area(); });
    std::cout << "smallest to largest:";
    for (const auto& s : shapes) std::cout << ' ' << s->name();
    std::cout << '\n';

    const Shape& ref = *shapes.back();              // references to an abstract class are fine
    std::cout << "largest is a " << ref.name() << '\n';
}
Output
circle: area 3.14159, perimeter 6.28319
rectangle: area 6, perimeter 10
square: area 4, perimeter 8
triangle: area 6, perimeter 12
smallest to largest: circle square rectangle triangle
largest is a triangle

The base class is now a contract: every shape has an area, a perimeter and a name. describe() is written once, in terms of those three, and works for shapes that did not exist when it was written. Square gets area and perimeter from Rectangle and only replaces name. Try to create a Shape:

What can you do with an abstract class?

final_class.cpp
struct Rectangle { virtual ~Rectangle() = default; };
struct Square final : Rectangle {};
struct Cube : Square {};
int main() {}
Compiler says
final_class.cpp:3:15: error: base 'Square' is marked 'final'
final_class.cpp:2:8: note: 'Square' declared here
Is a square a rectangle? Here Square derives from Rectangle safely because shapes cannot change after construction. If Rectangle had set_width(), a Square could not honor it without breaking its own invariant, and code written for rectangles would misbehave when handed a square. That is the Liskov substitution principle: a derived class must be usable everywhere its base is, keeping every promise the base makes.

Interfaces

An abstract class with only pure virtual functions (plus a virtual destructor) is what other languages call an interface. A class may implement several. Code that needs only one capability depends only on that interface, and dynamic_cast asks at run time whether an object supports another one:

interfaces.cppRun online ↗
// interfaces.cpp -- pure abstract "interface" classes, and a class that implements two of them
#include <iostream>
#include <memory>
#include <sstream>
#include <string>
#include <vector>

class Drawable {                                    // an interface: only pure virtual functions
public:
    virtual ~Drawable() = default;
    virtual void draw(std::ostream& out) const = 0;
};

class Serializable {
public:
    virtual ~Serializable() = default;
    virtual std::string to_json() const = 0;
};

class Point : public Drawable, public Serializable {   // implements both interfaces
public:
    Point(double x, double y) : x_(x), y_(y) {}
    void draw(std::ostream& out) const override { out << "* at (" << x_ << ", " << y_ << ")"; }
    std::string to_json() const override {
        std::ostringstream s;
        s << "{\"x\": " << x_ << ", \"y\": " << y_ << "}";
        return s.str();
    }
private:
    double x_, y_;
};

class Label : public Drawable {                     // drawable, but not serializable
public:
    explicit Label(std::string t) : text_(std::move(t)) {}
    void draw(std::ostream& out) const override { out << "\"" << text_ << "\""; }
private:
    std::string text_;
};

void render(const std::vector<std::unique_ptr<Drawable>>& scene) {   // depends only on the interface
    for (const auto& d : scene) {
        std::cout << "draw: ";
        d->draw(std::cout);
        // ask at run time whether this object also supports another interface
        if (auto s = dynamic_cast<const Serializable*>(d.get()))
            std::cout << "   json: " << s->to_json();
        std::cout << '\n';
    }
}

int main() {
    std::vector<std::unique_ptr<Drawable>> scene;
    scene.push_back(std::make_unique<Point>(1, 2));
    scene.push_back(std::make_unique<Label>("origin"));
    scene.push_back(std::make_unique<Point>(-3, 0.5));
    render(scene);
}
Output
draw: * at (1, 2)   json: {"x": 1, "y": 2}
draw: "origin"
draw: * at (-3, 0.5)   json: {"x": -3, "y": 0.5}

Multiple inheritance and the diamond

Inheriting implementation from two classes that share a base creates the diamond problem: without care, the object contains two copies of the shared base (quiz question 10 shows this). virtual inheritance makes the shared base appear once, and the most-derived class constructs it:

diamond.cppRun online ↗
// diamond.cpp -- multiple inheritance and the diamond problem, solved with virtual inheritance
#include <iostream>

struct Device {
    explicit Device(int id) : id(id) { std::cout << "Device(" << id << ")\n"; }
    int id;
};
struct Sensor : virtual Device {                 // virtual base: shared, not duplicated
    Sensor() : Device(-1) { std::cout << "Sensor()\n"; }
};
struct Actuator : virtual Device {
    Actuator() : Device(-2) { std::cout << "Actuator()\n"; }
};
struct Thermostat : Sensor, Actuator {
    Thermostat() : Device(7) { std::cout << "Thermostat()\n"; }   // the most derived class builds the virtual base
};

int main() {
    Thermostat t;
    std::cout << "one Device, id " << t.id << '\n';  // without "virtual", t.id would be ambiguous
    std::cout << "sizeof(Thermostat) = " << sizeof(Thermostat) << " bytes on this machine\n";
}
Output
Device(7)
Sensor()
Actuator()
Thermostat()
one Device, id 7
sizeof(Thermostat) = 24 bytes on this machine

Device(-1) and Device(-2) never ran: with a virtual base, only the most-derived class's choice counts. Multiple inheritance of interfaces is common and safe; diamonds of implementation are best avoided.

Key points

  • = 0 makes a function pure virtual and its class abstract; derived classes must implement it to be concrete.
  • Abstract base classes are contracts: write code against them, not against concrete classes.
  • Inherit interfaces freely; inherit implementation from one base where possible.
