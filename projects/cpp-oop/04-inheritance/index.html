Inheritance

A derived class contains a complete base-class object and adds to it. That makes it usable wherever the base is expected, with one trap that the next lesson removes.

Deriving a class

class Circle : public Shape makes Circle a derived class of the base class Shape. A Circle object contains a complete Shape inside it, inherits its member functions, and adds its own. Public inheritance means "is-a": a circle is a shape, so a Circle can be passed anywhere a Shape& or Shape* is expected.

inheritance.cppRun online ↗
// inheritance.cpp -- a derived class reuses and extends a base class (and a trap)
#include <iostream>
#include <string>

class Shape {
public:
    explicit Shape(std::string name) : name_(std::move(name)) {}
    std::string name() const { return name_; }
    double area() const { return 0.0; }        // a generic shape has no formula... so it returns 0?
protected:
    std::string name_;                         // derived classes may use it; outside code may not
};

class Circle : public Shape {                  // public inheritance: a Circle IS-A Shape
public:
    explicit Circle(double r) : Shape("circle"), r_(r) {}     // build the Shape part first
    double area() const { return 3.141592653589793 * r_ * r_; }   // hides Shape::area (not virtual!)
    double radius() const { return r_; }
    void rename(const std::string& n) { name_ = n; }          // protected member: allowed here
private:
    double r_;
};

void report(const Shape& s) {                  // accepts any Shape, including a Circle
    std::cout << "report: " << s.name() << " has area " << s.area() << '\n';
}

int main() {
    Circle c(2);
    std::cout << c.name() << " of radius " << c.radius() << " has area " << c.area() << '\n';
    c.rename("big circle");
    report(c);                                 // compiles, but prints area 0: Shape::area was called
    std::cout << "c.Shape::area() = " << c.Shape::area() << ", c.area() = " << c.area() << '\n';
}
Output
circle of radius 2 has area 12.5664
report: big circle has area 0
c.Shape::area() = 0, c.area() = 12.5664

Download inheritance.cpp compiled with -std=c++17 -Wall -Wextra

  • The derived constructor builds the base part first, by naming the base in its initializer list: : Shape("circle").
  • protected members are visible to derived classes but not to outside code, so rename can change name_. Use it sparingly: every protected member is an interface you promise to derived classes.
  • The trap: report(c) printed area 0. Inside report the compiler only knows it has "some Shape", and because area() is an ordinary function it calls Shape::area. Circle::area did not override it, it only hid it. Lesson 05 fixes this with virtual.

Almost all inheritance you write will be public. Private inheritance means "is implemented in terms of"; usually a member variable says that more clearly ("prefer composition to inheritance").

Reusing constructors and base functions

using Base::Base; inherits the base's constructors instead of rewriting each one, a delegating constructor lets one constructor call another of the same class, and Base::f() calls the base version of a function from inside an override, so the derived version can extend rather than replace it:

inherit_ctors.cppRun online ↗
// inherit_ctors.cpp -- reusing base constructors, and calling the base version of a function
#include <iostream>
#include <string>

class Account {
public:
    Account(std::string owner, double balance) : owner_(std::move(owner)), balance_(balance) {}
    explicit Account(std::string owner) : Account(std::move(owner), 0.0) {}   // delegating constructor
    virtual ~Account() = default;
    virtual void print() const { std::cout << owner_ << ": " << balance_; }
    void deposit(double x) { balance_ += x; }
protected:
    double balance() const { return balance_; }
private:
    std::string owner_;
    double balance_;
};

class Savings : public Account {
public:
    using Account::Account;                      // inherit both constructors instead of rewriting them
    void print() const override {
        Account::print();                        // reuse the base version, then add to it
        std::cout << " (savings, interest at 3%: " << balance() * 0.03 << ")";
    }
};

int main() {
    Savings s("Ada", 1000);
    s.deposit(200);
    s.print(); std::cout << '\n';
    Savings empty("Grace");
    const Account& a = empty;
    a.print(); std::cout << '\n';
}
Output
Ada: 1200 (savings, interest at 3%: 36)
Grace: 0 (savings, interest at 3%: 0)

What an object looks like in memory

Inheritance is not magic: a derived object is laid out as its base part followed by its own members. A class with virtual functions (lesson 05) also carries a hidden pointer, the vptr, usually at the very start. These numbers are measured, not assumed:

layout.cppRun online ↗
// layout.cpp -- what an object looks like in memory
#include <cstddef>
#include <iostream>

struct Point { double x, y; };                                   // plain data: just two doubles
struct Shape { virtual ~Shape() = default; virtual double area() const = 0; };
struct Circle : Shape { double r = 1; double area() const override { return 3.14159 * r * r; } };
struct Rect : Shape { double w = 1, h = 2; double area() const override { return w * h; } };

struct Drawable { virtual ~Drawable() = default; virtual void draw() const {} };
struct Serializable { virtual ~Serializable() = default; virtual void save() const {} };
struct Sprite : Drawable, Serializable { double x = 0; };      // two bases, two vptrs

int main() {
    std::cout << "sizeof(Point)  = " << sizeof(Point) << "   (2 doubles)\n";
    std::cout << "sizeof(Shape)  = " << sizeof(Shape) << "    (just the vptr)\n";
    std::cout << "sizeof(Circle) = " << sizeof(Circle) << "   (vptr + r)\n";
    std::cout << "sizeof(Rect)   = " << sizeof(Rect) << "   (vptr + w + h)\n";
    std::cout << "sizeof(Sprite) = " << sizeof(Sprite) << "   (2 vptrs + x)\n";

    Circle c;
    const char* base = reinterpret_cast<const char*>(&c);
    std::cout << "offset of r in Circle: " << reinterpret_cast<const char*>(&c.r) - base << " bytes\n";
    std::cout << "Shape part of c starts at offset " << reinterpret_cast<const char*>(static_cast<Shape*>(&c)) - base << '\n';

    Sprite s;
    const char* sb = reinterpret_cast<const char*>(&s);
    std::cout << "Drawable part of a Sprite at offset " << reinterpret_cast<const char*>(static_cast<Drawable*>(&s)) - sb << '\n';
    std::cout << "Serializable part of a Sprite at offset " << reinterpret_cast<const char*>(static_cast<Serializable*>(&s)) - sb
              << "  (converting the pointer adjusts its value)\n";
}
Output
sizeof(Point)  = 16   (2 doubles)
sizeof(Shape)  = 8    (just the vptr)
sizeof(Circle) = 16   (vptr + r)
sizeof(Rect)   = 24   (vptr + w + h)
sizeof(Sprite) = 24   (2 vptrs + x)
offset of r in Circle: 8 bytes
Shape part of c starts at offset 0
Drawable part of a Sprite at offset 0
Serializable part of a Sprite at offset 8  (converting the pointer adjusts its value)

Build a layout

Change the classes and see where every byte goes. Each of the 24 combinations was compiled and measured; nothing here is computed by the page.

With one base, a Circle* and the Shape* to the same object hold the same address. With two bases, converting a Sprite* to Serializable* changes the pointer's value by 8 bytes so that it points at the Serializable part. The compiler does this for you; it is why you should never convert between class pointers with reinterpret_cast or C-style casts through void*.

Key points

  • Public inheritance models is-a; prefer a member (composition) for has-a.
  • The base part is built first, by the base constructor named in the initializer list.
  • A non-virtual function with the same name in the derived class hides, it does not override.
