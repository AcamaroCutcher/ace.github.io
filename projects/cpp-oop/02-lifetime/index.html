Constructors, destructors and RAII

Every C++ object has a precisely defined lifetime. Knowing exactly when constructors and destructors run is what makes C++ resource management automatic.

The order of construction and destructionRAII: let the destructor clean upKey points

The order of construction and destruction

A constructor runs when an object is created; its destructor, ~ClassName(), runs when it is destroyed: at the closing brace for a local variable, at delete for an object made with new, when its owner is destroyed for a member. When a class has a base class and members, the parts are built in a fixed order (base, then members in declaration order, then the constructor body) and destroyed in exactly the reverse order:

lifetime.cppRun online ↗
// lifetime.cpp -- the order in which the parts of an object are built and destroyed
#include <iostream>
#include <string>

struct Logger {                       // a member that announces its own lifetime
    std::string name;
    explicit Logger(std::string n) : name(std::move(n)) { std::cout << "  + " << name << '\n'; }
    ~Logger() { std::cout << "  - " << name << '\n'; }
};

class Base {
public:
    Base() { std::cout << "Base()\n"; }
    virtual ~Base() { std::cout << "~Base()\n"; }    // virtual: see the section on destructors
};

class Derived : public Base {
    Logger log_{"member log_"};
public:
    Derived() { std::cout << "Derived()\n"; }
    ~Derived() override { std::cout << "~Derived()\n"; }
};

int main() {
    std::cout << "-- entering scope\n";
    {
        Derived d;                    // base first, then members, then the constructor body
        std::cout << "-- using d\n";
    }                                 // destroyed here, in exactly the reverse order
    std::cout << "-- left scope\n";

    std::cout << "-- on the heap, through a Base*\n";
    Base* p = new Derived;
    delete p;                         // ~Derived runs only because ~Base is virtual
}

RAII: let the destructor clean up

Because destructors always run, even when an exception is thrown, C++ ties resources to object lifetimes: the constructor acquires (opens a file, allocates memory, locks a mutex), the destructor releases. This is RAII, "resource acquisition is initialization", and it is why modern C++ rarely needs delete: std::unique_ptr, std::vector, std::string, std::lock_guard and std::fstream all clean up after themselves.

raii.cppRun online ↗
// raii.cpp -- Resource Acquisition Is Initialization: the destructor releases what the constructor took
#include <cstdio>
#include <iostream>
#include <memory>
#include <stdexcept>

class File {
public:
    File(const char* path, const char* mode) : f_(std::fopen(path, mode)) {
        if (!f_) throw std::runtime_error("cannot open file");
        std::cout << "opened " << path << '\n';
    }
    ~File() { std::fclose(f_); std::cout << "closed\n"; }    // runs on every exit path
    File(const File&) = delete;                              // one owner: copying is forbidden
    File& operator=(const File&) = delete;
    void write(const char* s) { std::fputs(s, f_); }
private:
    std::FILE* f_;
};

void save(bool fail) {
    File out("raii_demo.txt", "w");
    out.write("hello\n");
    if (fail) throw std::runtime_error("something went wrong mid-save");
    out.write("done\n");
}                                                           // ~File() here, or during the throw

int main() {
    save(false);
    try { save(true); } catch (const std::exception& e) { std::cout << "caught: " << e.what() << '\n'; }

    auto p = std::make_unique<int>(42);    // the standard library uses the same idea for memory
    std::cout << "*p = " << *p << " (freed automatically at the end of main)\n";
    std::remove("raii_demo.txt");
}
Output

closed
opened raii_demo.txt
closed
caught: something went wrong mid-save
*p = 42 (freed automatically at the end of main)

Note File(const File&) = delete;: copying a file handle would give two objects that both close the same file. The next lesson is about exactly this: what copying and moving an object should mean.

Key points

  • Construction: base, members (in declaration order), body. Destruction: the reverse, always.
  • A class used through base pointers needs a virtual destructor.
  • Own every resource through an object whose destructor releases it; then early returns and exceptions cannot leak.
