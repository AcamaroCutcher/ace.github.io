Security rules that matter

A container is a fence, not a vault. It keeps honest mistakes contained and makes attacks harder, but a determined attacker inside a misconfigured container can get out. These rules close the common holes:

RuleWhy
Never mount /var/run/docker.sock into a container you don't fully trustWhoever controls the Docker socket controls the host, as root
Avoid --privilegedIt removes nearly all isolation
Run as a non-root user (USER in the Dockerfile)If the program is compromised, the attacker isn't root inside
Mount only what's needed, read-only where possible (:ro)The container can't damage what it can't see or write
Bind private ports to 127.0.0.1Otherwise databases and admin pages are open to the network, and on Linux Docker's rules skip ufw
Use trusted, pinned, up-to-date imagesOld images carry old vulnerabilities. Rebuild and pull regularly
Scan images: docker scout cves IMAGE or TrivyLists known vulnerabilities in the packages inside
Limit resources (--memory, --cpus, --pids-limit)One runaway container can't freeze the machine
For hostile code, use a VM, gVisor or a micro-VMThey don't share the host kernel's attack surface

Keeping secrets out of images

Passwords, API keys and tokens must never be COPY-ed into an image or set with ENV in a Dockerfile; they would be readable by anyone with the image. Instead:

  • At run time: -e NAME (copied from your shell), --env-file .env, or Compose's .env file. Keep .env in .gitignore and .dockerignore.
  • At build time (for example, a token to download a private package), mount it for one step only, so it's never stored in a layer:
DockerfileDockerfile
# syntax=docker/dockerfile:1FROM python:3.13-slimRUN --mount=type=secret,id=pip_token \    PIP_INDEX_URL="https://$(cat /run/secrets/pip_token)@pypi.example.com/simple" pip install private-package
Terminalshell
docker build --secret id=pip_token,env=PIP_TOKEN -t app .

Troubleshooting

SymptomCause and fix
Cannot connect to the Docker daemonDocker isn't running. Start Docker Desktop (or sudo systemctl start docker on Linux).
permission denied … docker.sock (Linux)Your user isn't in the docker group: sudo usermod -aG docker $USER, then log out and in.
port is already allocatedAnother container or program uses that host port. docker ps to find it, or choose another: -p 8081:80.
Browser: connection reset / empty replyThe program inside listens on 127.0.0.1. Make it listen on 0.0.0.0 (lesson 05).
The container exits immediatelyA container lives as long as its main program. Read why with docker logs NAME; for a shell, use -it.
exec format errorThe image is for another CPU type (arm64 vs amd64). Rebuild with --platform, or pull a multi-arch image.
My changes disappearedThey were in the container's writable layer. Use a volume or bind mount for anything you want to keep.
localhost doesn't reach my computer from insideInside a container, localhost is the container. Use host.docker.internal (Docker Desktop; on Linux add --add-host=host.docker.internal:host-gateway).
Containers can't find each otherPut them on the same network; Compose does this, then use the service name as host name.
Files created in a bind mount belong to root (Linux)Run with --user "$(id -u):$(id -g)".
no space left on devicedocker system df, then docker system prune. On a Mac, Docker Desktop's disk size is set in its settings.
My code change doesn't show upThe image is stale: rebuild (docker compose up -d --build). With a bind mount, check the path.
