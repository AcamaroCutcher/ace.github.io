6.1The whole machine in one picture

Strip away the product and an LLM is one function: given a sequence of tokens, it returns a probability for every possible next token. Everything else (chatting, writing code, calling tools) comes from running that function in a loop: pick a next token, append it, run again.

Press Generate next token and follow one step through the pipeline. The probabilities in this demo come from a tiny statistical model trained on this page's own text, so it runs instantly in your browser; in Claude, the box in the middle is a deep transformer with a very large number of learned parameters. The shape of the computation is the same.

Key idea

An LLM does not retrieve answers from a database or run a hidden program for each task. It computes a distribution over the next token from the tokens it is given, and that one skill, scaled up enormously, produces everything you see.

What is public, and what is not

Anthropic has described Claude as a transformer-based language model, pretrained on a large text corpus and then fine-tuned with methods including reinforcement learning from human feedback and Constitutional AI. Details such as its number of parameters, exact architecture and training data mix are not public. This lesson explains the standard, published design that models of this family share, and says so whenever it describes something Claude-specific.

6.2Tokens: how text becomes numbers

Neural networks work on numbers, so text is first cut into tokens and each token is replaced by an integer ID. Modern LLMs use subword tokens, learned from data with algorithms like byte-pair encoding (BPE): start from single characters (or bytes), then repeatedly merge the most frequent adjacent pair into a new token. Common words become a single token; rare words are split into pieces; any string can still be represented.

Move the slider to learn more merges and watch the test sentence get shorter in tokens. This is exactly the algorithm in bpe.py.

Why you care as an agent builder
  • Pricing, speed and the context window are all measured in tokens, not words. English averages roughly 3–4 characters per token; code, numbers and other languages often use more tokens per character.
  • Tokenization explains classic LLM quirks: counting letters in a word is hard when the model sees "strawberry" as a few chunks, not ten letters.

"""
bpe.py - byte-pair encoding, the way language models (including Claude) cut text into tokens.

A model doesn't read letters or words. It reads integer token IDs. BPE learns the token
vocabulary from data:

    1. start with single characters (real tokenizers start with the 256 possible bytes)
    2. count every adjacent pair of tokens in the training text
    3. merge the most frequent pair into one new token; remember the merge
    4. repeat until the vocabulary is big enough (real models: ~50,000 - 200,000 tokens)

Encoding new text replays the merges in the order they were learned.
Claude's own tokenizer is not public, but it is a learned subword tokenizer of this family.

Run:  python bpe.py
No packages needed.
"""
from collections import Counter

TEXT = """an agent perceives its environment through sensors and acts upon that environment
through actuators. a rational agent selects the action that is expected to maximize its
performance measure. the agent program runs on the agent architecture. a learning agent
can improve its performance. an agent that plans considers the future consequences of actions."""


def pair_counts(words):
    counts = Counter()
    for word, freq in words.items():
        for a, b in zip(word, word[1:]):
            counts[(a, b)] += freq
    return counts


def merge_word(word, pair):
    out, i = [], 0
    while i < len(word):
        if i < len(word) - 1 and (word[i], word[i + 1]) == pair:
            out.append(word[i] + word[i + 1])
            i += 2
        else:
            out.append(word[i])
            i += 1
    return tuple(out)


def train(text, num_merges):
    # pre-split on spaces and mark word starts with "_" (GPT-style tokenizers use a similar trick)
    words = Counter(tuple("_" + w) for w in text.split())
    merges = []
    for _ in range(num_merges):
        counts = pair_counts(words)
        if not counts:
            break
        best = max(counts, key=lambda p: (counts[p], p))   # ties broken deterministically
        merges.append(best)
        words = Counter({merge_word(w, best): f for w, f in words.items()})
    return merges


def encode(text, merges):
    tokens = []
    for w in text.split():
        word = tuple("_" + w)
        for pair in merges:
            word = merge_word(word, pair)
        tokens.extend(word)
    return tokens


if __name__ == "__main__":
    merges = train(TEXT, 40)
    print("First 12 merges learned:")
    for i, (a, b) in enumerate(merges[:12]):
        print(f"  {i + 1:2d}. {a!r} + {b!r} -> {a + b!r}")
    vocab = sorted({t for t in encode(TEXT, merges)})
    ids = {t: i for i, t in enumerate(vocab)}
    sample = "the agent acts rationally"
    toks = encode(sample, merges)
    print(f"\n{sample!r}\n  tokens: {toks}\n  {len(sample)} characters -> {len(toks)} tokens")
    print("  ids:   ", [ids.get(t, -1) for t in toks], "  (-1 = not in this tiny vocabulary)")

6.3Next-token prediction, sampling and temperature

The model's output for each position is a vector of logits, one score per token in the vocabulary. Softmax turns scores into probabilities. Then the program that runs the model samples a token from that distribution. Choices here change the output a lot:

  • Greedy decoding always takes the most likely token. Deterministic, but often repetitive.
  • Temperature T divides the logits before softmax: T < 1 sharpens the distribution (safer, blander), T > 1 flattens it (more surprising, more errors).
  • Top-k keeps only the k most likely tokens before sampling.

The widget below is a character-level n-gram model: it predicts the next character from the previous n−1 characters by counting how often each continuation appeared in its training text (the corpus is shown below the widget). An LLM replaces counting with a neural network that generalizes, but the interface (context in, distribution out, sample) is identical.

P(token i) = exp(zi / T) / Σj exp(zj / T)Softmax with temperature T over the logits z.

6.4Attention: how tokens look at each other

An n-gram model only sees a fixed short window, and it cannot know that in "the robot saw the wall, so it stopped" the word "it" refers to the robot. Self-attention solves this. Every token is represented by a vector (its embedding plus position information). For each token, the network computes three vectors with learned matrices:

  • a query q: "what am I looking for?"
  • a key k: "what do I contain?"
  • a value v: "what will I pass on if you attend to me?"

The token's output is a weighted average of all values, weighted by how well its query matches each key:

Attention(Q, K, V) = softmax( Q Kᵀ / √d ) VScaled dot-product attention (Vaswani et al., 2017). In a language model a causal mask hides future tokens, so position t only attends to positions ≤ t.

Drag the query (the purple arrow) and the keys in the 2-D example below. Watch the dot products, the softmax weights, and the output (the star), which is the weighted average of the values. The sharpness slider plays the role of 1/√d: larger scores make attention focus on one key.

Real models use vectors with thousands of dimensions, and many attention heads in parallel (each with its own Q, K, V matrices), so different heads can track different relations: one follows grammar, another tracks which object a pronoun refers to, another copies a name seen earlier. The heads' outputs are concatenated and mixed by another learned matrix.

Concept

6.5The transformer block and the size of a model

A transformer is a stack of identical blocks. Each block does two things to every position's vector, each wrapped in a residual connection (the input is added back to the output) and a normalization layer:

  1. Causal self-attention: mix in information from earlier positions.
  2. A feed-forward network (MLP): transform each position's vector on its own; this is where much of the model's stored knowledge appears to live.

After the last block, a final layer maps each vector to logits over the vocabulary. That is the entire architecture: tiny_gpt.py below implements it in about 60 lines. What makes frontier models powerful is scale (width, depth, data and compute) and training, not a secret extra component. Count parameters yourself:

6.6Training: gradient descent on next-token loss

All those parameters start as random numbers. Pretraining adjusts them so that the model assigns high probability to the actual next token in a huge amount of text. The measure is cross-entropy loss: −log P(correct next token), averaged over positions. Each training step computes the loss on a batch of text, computes its gradient with respect to every parameter (backpropagation), and moves each parameter a little downhill. Repeat for trillions of tokens.

The widget trains the smallest possible neural language model, a bigram network (one weight matrix: previous character → logits for the next), live in your browser. Watch the loss fall from random guessing (ln of the vocabulary size) toward the best a bigram model can do, and watch the samples go from noise to word-like strings.

Key idea

Nobody programs the knowledge in. Predicting the next token well, over enough varied text, forces the network to learn spelling, grammar, facts, styles and patterns of reasoning, because all of them help predict what comes next.

"""
tiny_gpt.py - a complete, trainable GPT-style language model in about 150 lines of PyTorch.

This is the same architecture family as Claude, scaled down by a factor of roughly a million:
token embeddings + position embeddings -> N transformer blocks (causal self-attention + MLP)
-> a linear layer that scores every possible next token. Training is next-token prediction
with cross-entropy loss. Generation samples one token at a time and feeds it back in.

What it does NOT have (and Claude does): billions of parameters, trillions of training tokens,
a learned subword tokenizer, instruction tuning and RLHF / Constitutional AI, tool use.

Run:  pip install torch
      python tiny_gpt.py                    # trains on the built-in text for ~1-3 minutes on a laptop CPU
      python tiny_gpt.py my_corpus.txt      # or on any plain-text file (a few hundred KB is plenty)

Inspired by Andrej Karpathy's nanoGPT (now succeeded by his nanochat) and his "Let's build GPT"
lecture, which are the next step.
"""
import math
import sys

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# ------------------------------------------------------------------ hyperparameters
BLOCK = 64        # context length: how many previous characters the model can see
EMBED = 96        # width of every token vector
HEADS = 4         # attention heads per block
LAYERS = 3        # transformer blocks
STEPS = 2000
BATCH = 32
LR = 3e-3

def default_text(n=4000, seed=0):
    """Sentences from a tiny grammar. The model can't memorize them all, so it must learn the
    pattern: spelling, word order, and which words go together."""
    import random
    rng = random.Random(seed)
    who = ["the robot", "the agent", "a small rover", "the vacuum", "my drone", "the arm"]
    verb = ["moves to", "looks at", "drives toward", "maps", "cleans", "avoids", "inspects"]
    what = ["the kitchen", "a red box", "the charging dock", "the wall", "the door", "a sample"]
    why = ["because the battery is low", "to reach its goal", "after it senses dirt",
           "when the path is clear", "while it plans", "before it stops"]
    return "".join(f"{rng.choice(who)} {rng.choice(verb)} {rng.choice(what)} {rng.choice(why)}. "
                   for _ in range(n))


# ------------------------------------------------------------------ data: characters as tokens
text = open(sys.argv[1], encoding="utf-8").read() if len(sys.argv) > 1 else default_text()
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
encode = lambda s: [stoi[c] for c in s]
decode = lambda ids: "".join(itos[i] for i in ids)
data = torch.tensor(encode(text), dtype=torch.long)
split = int(0.9 * len(data))
train_data, val_data = data[:split], data[split:]


def batch(source):
    ix = torch.randint(len(source) - BLOCK - 1, (BATCH,))
    x = torch.stack([source[i:i + BLOCK] for i in ix])
    y = torch.stack([source[i + 1:i + BLOCK + 1] for i in ix])    # targets: the next character
    return x, y


# ------------------------------------------------------------------ the model
class CausalSelfAttention(nn.Module):
    """Every position looks at earlier positions and takes a weighted average of their values.

    weights = softmax( Q K^T / sqrt(d) ), with future positions masked out (the "causal" part).
    """

    def __init__(self):
        super().__init__()
        self.qkv = nn.Linear(EMBED, 3 * EMBED)
        self.proj = nn.Linear(EMBED, EMBED)
        self.register_buffer("mask", torch.tril(torch.ones(BLOCK, BLOCK)).view(1, 1, BLOCK, BLOCK))

    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(EMBED, dim=2)
        # (B, T, C) -> (B, heads, T, head_size)
        q, k, v = [t.view(B, T, HEADS, C // HEADS).transpose(1, 2) for t in (q, k, v)]
        att = (q @ k.transpose(-2, -1)) / math.sqrt(k.size(-1))
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
        att = F.softmax(att, dim=-1)
        y = (att @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(y)


class Block(nn.Module):
    def __init__(self):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(EMBED), nn.LayerNorm(EMBED)
        self.attn = CausalSelfAttention()
        self.mlp = nn.Sequential(nn.Linear(EMBED, 4 * EMBED), nn.GELU(), nn.Linear(4 * EMBED, EMBED))

    def forward(self, x):
        x = x + self.attn(self.ln1(x))     # residual connections let information flow straight through
        x = x + self.mlp(self.ln2(x))
        return x


class TinyGPT(nn.Module):
    def __init__(self, vocab):
        super().__init__()
        self.tok = nn.Embedding(vocab, EMBED)       # token id -> vector
        self.pos = nn.Embedding(BLOCK, EMBED)       # position -> vector
        self.blocks = nn.Sequential(*[Block() for _ in range(LAYERS)])
        self.ln = nn.LayerNorm(EMBED)
        self.head = nn.Linear(EMBED, vocab)         # vector -> a score (logit) for every next token

    def forward(self, idx, targets=None):
        T = idx.size(1)
        x = self.tok(idx) + self.pos(torch.arange(T, device=idx.device))
        logits = self.head(self.ln(self.blocks(x)))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, n, temperature=0.8, top_k=None):
        for _ in range(n):
            logits, _ = self(idx[:, -BLOCK:])
            logits = logits[:, -1, :] / temperature           # only the last position predicts the future
            if top_k:
                v, _ = torch.topk(logits, top_k)
                logits[logits < v[:, [-1]]] = -float("inf")
            probs = F.softmax(logits, dim=-1)
            nxt = torch.multinomial(probs, 1)                 # sample, don't just take the max
            idx = torch.cat([idx, nxt], dim=1)
        return idx


model = TinyGPT(len(chars))
print(f"vocabulary: {len(chars)} characters, parameters: {sum(p.numel() for p in model.parameters()):,}")
opt = torch.optim.AdamW(model.parameters(), lr=LR)


@torch.no_grad()
def val_loss():
    model.eval()
    losses = [model(*batch(val_data))[1].item() for _ in range(10)]
    model.train()
    return sum(losses) / len(losses)


for step in range(STEPS + 1):
    x, y = batch(train_data)
    _, loss = model(x, y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    opt.step()
    if step % 250 == 0:
        print(f"step {step:5d}   train loss {loss.item():.3f}   val loss {val_loss():.3f}"
              f"   (random guessing = {math.log(len(chars)):.3f})")

prompt = "the robot"
out = model.generate(torch.tensor([encode(prompt)]), 200)
print("\n--- sample ---\n" + decode(out[0].tolist()))

6.8From a text predictor to an assistant

A model fresh from pretraining (a base model) continues text; it does not answer questions helpfully or follow instructions reliably. Turning it into an assistant like Claude takes further training stages. The broad recipe used across the field, and described publicly by Anthropic for Claude, is:

  1. Pretraining on a very large, diverse corpus to predict the next token.
  2. Supervised fine-tuning on example conversations that show the desired behavior.
  3. Reinforcement learning from feedback: RLHF with human preference comparisons, and Anthropic's Constitutional AI, where an AI model critiques and compares responses according to a written set of principles (lesson 05 explains the RL part). Models are also trained to use tools and to reason step by step.

Even after all this, the model is still a next-token predictor; it has learned that in a conversation formatted a certain way, the most likely continuation of an assistant turn is a helpful, honest answer, or a request to use a tool.

Illustrative, not literal

The "model's view" tab shows the idea: the whole conversation, including tool definitions and results, becomes one sequence of tokens with special markers between turns. Claude's actual internal formatting is not public, so the markers here are made up for teaching.

6.9What follows from this design

  • The context window is the only working memory. Everything the model uses in a reply must be in the tokens it is given: system prompt, tool definitions, the conversation, tool results. Recent Claude models accept up to about a million tokens, but every token costs time and money, and long contexts must still be managed (lesson 07).
  • Knowledge has a cutoff. The weights only know what was in the training data, up to a date. For anything newer or specific to you, the agent must look it up with tools.
  • Plausible is not the same as true. The training objective rewards likely text. Models are trained to be honest and to say when they are unsure, but checking (running the code, reading the source) beats trusting.
  • Reasoning costs tokens. When a model "thinks" before answering, it generates intermediate reasoning tokens; that is extra computation the model can use for hard problems. Modern Claude models do this adaptively, thinking more on harder problems.
  • Sampling makes outputs vary. The same prompt can give different answers. Agents must be robust to that: validate tool inputs, check results, retry.
