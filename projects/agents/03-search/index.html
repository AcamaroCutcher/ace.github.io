3.1Problem-solving agents

A problem-solving agent is a goal-based agent in an environment that is (assumed to be) fully observable, deterministic and known. In such a world the agent can plan a whole sequence of actions in its head before moving. It works in four phases:

  1. Goal formulation: decide what you want (be in Bucharest tomorrow).
  2. Problem formulation: decide which states and actions to consider (cities and roads, not every step of the steering wheel). This is abstraction, and choosing it well is half the work.
  3. Search: simulate action sequences in the model until one reaches the goal.
  4. Execution: carry out the solution. Because the world is assumed deterministic, the agent can execute with its eyes closed (an open-loop system). If that assumption may fail, it must watch percepts and re-plan (closed loop), which is what real robots do.
A search problem has five parts
  • States and an initial state: In(Arad)
  • Goal test (one or more goal states): In(Bucharest)
  • ACTIONS(s): the actions applicable in s: drive to any neighboring city
  • Transition model RESULT(s, a): the state after doing a in s
  • ACTION-COST(s, a, s′): the road distance. A solution's cost is the sum along its path; an optimal solution has the lowest cost.

Look at the class RouteProblem in search.py at the end of this lesson: it is exactly these five parts as five methods. Any problem you can write in this shape (route finding, the 8-puzzle, robot motion, scheduling) can be solved by the same search code.

3.2Search trees, nodes and the frontier

Search algorithms grow a search tree whose root is the initial state. A node in the tree stores a state, a pointer to its parent, the action that led to it and the path cost g(n) from the root. Different nodes can contain the same state (Arad → Sibiu → Arad is a legal but silly path).

The algorithm keeps a frontier: nodes that have been generated but not yet expanded. It repeatedly picks one node from the frontier, checks whether it is a goal, and if not, expands it by generating its children. The only difference between search algorithms is which frontier node they pick next. To avoid wasting work on repeated states, a graph search also keeps a table of states already reached and the cheapest path found to each.

Key idea

Breadth-first, uniform-cost, greedy and A* are the same loop with a different priority f(n) for the frontier: depth, path cost g, heuristic h, and g + h.

3.4Best-first search: book ↔ code

Book-style pseudocode (paraphrased from 4e Fig. 3.7)
function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure  node ← NODE(STATE = problem.INITIAL)  frontier ← priority queue ordered by f, containing node  reached ← table {problem.INITIAL: node}  while not IS-EMPTY(frontier) do    node ← POP(frontier)    if problem.IS-GOAL(node.STATE) then return node    for each child in EXPAND(problem, node) do      s ← child.STATE      if s not in reached or child.PATH-COST < reached[s].PATH-COST then        reached[s] ← child        add child to frontier  return failure

3.5Uninformed strategies

Uninformed (blind) strategies use no knowledge about where the goal is; they only know how to generate successors and recognize a goal. They differ in their frontier discipline. The book compares them on four criteria: completeness (finds a solution if one exists), cost optimality (finds the cheapest), time and space complexity, in terms of the branching factor b, the depth of the shallowest solution d, the maximum depth m, the optimal cost C* and the smallest action cost ε.

StrategyFrontierComplete?Optimal?TimeSpace
Breadth-firstFIFO queueYes (finite b)Only if all steps cost the sameO(bd)O(bd)
Uniform-costPriority on gYes (costs ≥ ε > 0)YesO(b1+⌊C*/ε⌋)same
Depth-firstLIFO stackNo (yes in finite graphs)NoO(bm)O(bm)
Iterative deepeningDFS with growing depth limitYesOnly if all steps cost the sameO(bd)O(bd)

Exponential growth is the enemy. With b = 10 and a million nodes per second, depth 10 takes about three hours and needs terabytes of memory for breadth-first search. That is why we need knowledge: heuristics.

3.6Heuristics and A*

An informed search uses a heuristic h(n): an estimate of the cost of the cheapest path from n to a goal. Straight-line distance is a heuristic for road distance: easy to compute, and never more than the true distance.

f(n) = g(n) + h(n)A*: cost so far + estimated cost to go = estimated cost of the cheapest solution through n
  • Admissible: h never overestimates. Then A* (tree search) returns an optimal solution. Intuition: an optimistic estimate cannot make A* skip the true best path, because that path's f is never above the optimal cost.
  • Consistent: h(n) ≤ c(n, a, n′) + h(n′), the triangle inequality. Every consistent heuristic is admissible, f never decreases along a path, and A* graph search is optimal and never needs to re-open a state.
  • Dominance: if h₂(n) ≥ h₁(n) everywhere and both are admissible, h₂ is better: A* with h₂ never expands more nodes. Bigger is better, as long as it stays admissible.
  • Weighted A* uses g + W·h with W > 1: it trusts the heuristic more, expands fewer nodes, and gives up optimality (bounded by a factor W). Try it in the grid lab.
  • Greedy best-first uses only h: fast, often good, not optimal (Romania: 450 km instead of 418).

Good heuristics often come from relaxed problems: remove a constraint and solve the easier problem exactly. Grid distance ignoring walls (Manhattan distance) is the exact cost of a relaxed problem with no walls, so it is admissible.

3.8The 8-puzzle: heuristics you can feel

The book's other classic example. A state is an arrangement of eight tiles; an action slides a tile into the gap. Two admissible heuristics: h₁, the number of misplaced tiles, and h₂, the sum of the Manhattan distances of the tiles from their goal squares. Shuffle, try to solve it yourself, then race the algorithms. Watch how many states each one expands: with a deep shuffle, A* with h₂ expands a small fraction of what uniform-cost search does, and both find the same optimal number of moves.

"""
search.py - AIMA Chapter 3: problem-solving agents and search.

One generic BEST-FIRST-SEARCH (AIMA 4e Figure 3.7) gives you every algorithm in the chapter by
changing only the priority f(n) used to order the frontier:

    breadth-first   f(n) = depth(n)          (FIFO queue)
    uniform-cost    f(n) = g(n)              (path cost so far; Dijkstra's algorithm)
    greedy          f(n) = h(n)              (estimated cost to the goal)
    A*              f(n) = g(n) + h(n)
    weighted A*     f(n) = g(n) + W*h(n)     (W > 1: faster, not always optimal)

The example is the book's road map of Romania (3e Figure 3.2, 4e Figure 3.1) with straight-line
distances to Bucharest as the heuristic (3e Figure 3.22, 4e Figure 3.16).

Run:  python search.py
No packages needed.
"""
import heapq
import itertools

# ---------------------------------------------------------------------- the problem
ROADS = {  # undirected road distances in km (AIMA 3e Fig. 3.2, 4e Fig. 3.1)
    ("Arad", "Zerind"): 75, ("Arad", "Sibiu"): 140, ("Arad", "Timisoara"): 118,
    ("Zerind", "Oradea"): 71, ("Oradea", "Sibiu"): 151, ("Timisoara", "Lugoj"): 111,
    ("Lugoj", "Mehadia"): 70, ("Mehadia", "Drobeta"): 75, ("Drobeta", "Craiova"): 120,
    ("Craiova", "Rimnicu Vilcea"): 146, ("Craiova", "Pitesti"): 138, ("Sibiu", "Fagaras"): 99,
    ("Sibiu", "Rimnicu Vilcea"): 80, ("Rimnicu Vilcea", "Pitesti"): 97,
    ("Fagaras", "Bucharest"): 211, ("Pitesti", "Bucharest"): 101, ("Bucharest", "Giurgiu"): 90,
    ("Bucharest", "Urziceni"): 85, ("Urziceni", "Hirsova"): 98, ("Hirsova", "Eforie"): 86,
    ("Urziceni", "Vaslui"): 142, ("Vaslui", "Iasi"): 92, ("Iasi", "Neamt"): 87,
}
SLD_BUCHAREST = {  # straight-line distance to Bucharest: an admissible heuristic
    "Arad": 366, "Bucharest": 0, "Craiova": 160, "Drobeta": 242, "Eforie": 161, "Fagaras": 176,
    "Giurgiu": 77, "Hirsova": 151, "Iasi": 226, "Lugoj": 244, "Mehadia": 241, "Neamt": 234,
    "Oradea": 380, "Pitesti": 100, "Rimnicu Vilcea": 193, "Sibiu": 253, "Timisoara": 329,
    "Urziceni": 80, "Vaslui": 199, "Zerind": 374,
}


class RouteProblem:
    """The five parts of a search problem (AIMA Section 3.1)."""

    def __init__(self, initial, goal, roads):
        self.initial = initial                       # 1. initial state
        self.goal = goal
        self.neighbors = {}
        for (a, b), d in roads.items():
            self.neighbors.setdefault(a, {})[b] = d
            self.neighbors.setdefault(b, {})[a] = d

    def actions(self, state):                        # 2. ACTIONS(s): drive to a neighbor
        return sorted(self.neighbors[state])

    def result(self, state, action):                 # 3. RESULT(s, a): transition model
        return action

    def is_goal(self, state):                        # 4. goal test
        return state == self.goal

    def action_cost(self, s, a, s2):                 # 5. ACTION-COST(s, a, s')
        return self.neighbors[s][s2]


class Node:
    def __init__(self, state, parent=None, path_cost=0.0, depth=0):
        self.state, self.parent, self.path_cost, self.depth = state, parent, path_cost, depth

    def path(self):
        node, out = self, []
        while node:
            out.append(node.state)
            node = node.parent
        return out[::-1]


def expand(problem, node):
    for a in problem.actions(node.state):
        s2 = problem.result(node.state, a)
        cost = node.path_cost + problem.action_cost(node.state, a, s2)
        yield Node(s2, node, cost, node.depth + 1)


def best_first_search(problem, f, early_goal_test=False):
    """AIMA 4e Figure 3.7. Returns (goal node or None, number of nodes expanded, expansion order)."""
    node = Node(problem.initial)
    counter = itertools.count()                      # tie-breaker: first in, first out
    frontier = [(f(node), next(counter), node)]
    reached = {problem.initial: node}
    expanded = []
    while frontier:
        _, _, node = heapq.heappop(frontier)
        if problem.is_goal(node.state):
            return node, len(expanded), expanded
        expanded.append(node.state)
        for child in expand(problem, node):
            s = child.state
            if s not in reached or child.path_cost < reached[s].path_cost:
                reached[s] = child
                if early_goal_test and problem.is_goal(s):   # breadth-first can stop here
                    return child, len(expanded), expanded
                heapq.heappush(frontier, (f(child), next(counter), child))
    return None, len(expanded), expanded


def breadth_first(problem):
    # breadth-first never revisits a reached state, even through a cheaper path
    node = Node(problem.initial)
    if problem.is_goal(node.state):
        return node, 0, []
    frontier, reached, expanded = [node], {problem.initial}, []
    while frontier:
        node = frontier.pop(0)
        expanded.append(node.state)
        for child in expand(problem, node):
            if problem.is_goal(child.state):
                return child, len(expanded), expanded
            if child.state not in reached:
                reached.add(child.state)
                frontier.append(child)
    return None, len(expanded), expanded


def uniform_cost(problem):
    return best_first_search(problem, lambda n: n.path_cost)


def greedy(problem, h):
    return best_first_search(problem, lambda n: h(n.state))


def astar(problem, h, weight=1.0):
    return best_first_search(problem, lambda n: n.path_cost + weight * h(n.state))


if __name__ == "__main__":
    problem = RouteProblem("Arad", "Bucharest", ROADS)
    h = SLD_BUCHAREST.get
    runs = [
        ("breadth-first", breadth_first(problem)),
        ("uniform-cost", uniform_cost(problem)),
        ("greedy best-first", greedy(problem, h)),
        ("A*", astar(problem, h)),
        ("weighted A* (W=2)", astar(problem, h, 2.0)),
    ]
    for name, (node, n_expanded, order) in runs:
        print(f"{name:18s} cost {node.path_cost:4.0f} km   expanded {n_expanded:2d}   path: {' -> '.join(node.path())}")
    print("\nA* expansion order (compare with AIMA Figure 3.18 in 4e / 3.24 in 3e):")
    _, _, order = astar(problem, h)
    print("  " + ", ".join(order))

3.10Search in robots and in LLM agents

Robots use exactly this machinery. A mobile robot's map is a grid or graph, and A* (or relatives like D* Lite, which re-plans quickly when the map changes) plans its path; lesson 09 uses it. Robot arms search in a continuous configuration space with sampling planners such as RRT.

LLM agents mostly do not run an explicit search algorithm. When Claude Code fixes a bug, it does something closer to greedy best-first search with a learned heuristic: at each step the model proposes the action that looks most promising given everything in its context, observes the result, and continues. It backtracks when a result is bad ("that didn't work, let me try…"). Research systems add explicit search on top of LLMs (sampling several candidate steps and scoring them, as in tree-of-thought methods), which is A*-like thinking with the LLM as both successor function and heuristic.

Why this lesson still matters for LLM agents

When you build an agent and it loops, wanders or gives up too early, the diagnosis is usually in this chapter's vocabulary: no memory of reached states (it retries the same failed command), a bad heuristic (it chases the wrong file), no cost model (it takes an expensive path), or no completeness guarantee (it never considers the right action).
