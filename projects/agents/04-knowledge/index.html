4.1Knowledge-based agents

The agents so far kept knowledge in special-purpose forms: a vacuum's map, a search problem's transition model. A knowledge-based agent keeps it in a general form: a knowledge base (KB), a set of sentences in a formal language. The agent interacts with it through two operations:

  • TELL adds a sentence: what the agent perceived, or a fact about the world ("there is no breeze in [1,1]").
  • ASK poses a question, answered by inference: deriving new sentences that follow from the KB ("is [1,2] safe?").

The appeal is that the agent's designer can describe what is true about the world (declaratively) and let a general inference procedure work out what to do. The same reasoning engine works for any world you can describe.

Book-style pseudocode (paraphrased from Fig. 7.1)
function KB-AGENT(percept) returns an action  TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))  action ← ASK(KB, MAKE-ACTION-QUERY(t))  TELL(KB, MAKE-ACTION-SENTENCE(action, t))  t ← t + 1  return action

4.2The wumpus world

The book's test bed is a cave of 4×4 rooms. Somewhere there is gold; somewhere there is the wumpus, a beast that eats anyone who enters its room; some rooms contain bottomless pits (each room other than the start has one with probability 0.2). The agent starts in [1,1] and sees nothing directly. It only gets local percepts:

  • a Stench in rooms next to the wumpus (not diagonally);
  • a Breeze in rooms next to a pit;
  • Glitter in the room with the gold (plus Bump and Scream, which this simplified version leaves out).

In the full book version the agent turns, moves forward, grabs, shoots its single arrow and climbs out; the performance measure is +1000 for leaving with the gold, −1000 for dying, −1 per action and −10 for the arrow. The environment is partially observable, deterministic, sequential, static, discrete and single-agent (the wumpus does not move): the difficulty is purely reasoning under partial observability.

4.4Logic, models and entailment

A logic has a syntax (which sentences are well formed), and a semantics (when a sentence is true). In propositional logic, sentences are built from symbols such as P₁,₂ ("there is a pit in [1,2]") and B₁,₁ ("there is a breeze in [1,1]") with the connectives ¬ (not), ∧ (and), ∨ (or), ⇒ (implies) and ⇔ (if and only if).

A model is a possible world: an assignment of true or false to every symbol. A sentence is true in some models and false in others. The central idea of the chapter is entailment:

KB ⊨ α   if and only if   α is true in every model in which KB is true  (M(KB) ⊆ M(α))"α follows from the KB": whatever the world is like, if the KB is right, α is right too.

The simplest way to decide entailment is model checking: enumerate all models, keep those where the KB is true, and check α in each. With n symbols there are 2n models, so it is exponential, but it is sound (it never derives something false) and complete (it derives everything that is entailed). The agent above uses it on the few rooms next to visited ones.

The book's example KB after the agent has visited [1,1] and [2,1]:

RuleSentenceMeaning
R₁¬P₁,₁No pit in the start room
R₂B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)A breeze in [1,1] means a pit next to it (and vice versa)
R₃B₂,₁ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₃,₁)The same rule for [2,1]
R₄¬B₁,₁Percept: no breeze in [1,1]
R₅B₂,₁Percept: breeze in [2,1]

4.6Beyond enumeration: proofs, SAT and planning

Enumerating models is hopeless for large KBs, so the chapter develops faster methods:

  • Theorem proving applies inference rules (modus ponens, and-elimination, resolution) to derive α directly, without listing models. Resolution is complete for propositional logic.
  • Forward and backward chaining work in linear time for Horn clauses (rules of the form A ∧ B ⇒ C), the basis of rule engines and Prolog.
  • SAT solvers (DPLL, WalkSAT, and modern CDCL solvers) decide satisfiability for millions of clauses; checking KB ⊨ α is the same as checking that KB ∧ ¬α is unsatisfiable.
  • First-order logic (Ch. 8–9) adds objects, relations and quantifiers ("every square adjacent to a pit is breezy" in one sentence instead of sixteen).
  • Planning (3e Ch. 10, 4e Ch. 11) describes actions by preconditions and effects (the PDDL language) and searches for plans with domain-independent heuristics.

4.7When logic is not enough: probability

Logic answers "true in all models", "false in all models", or "unknown". When the agent is boxed in and every move is risky, "unknown" is useless; it needs to know how likely each danger is. The book revisits the wumpus world with probabilities: each room has a pit with prior probability 0.2. Weigh each consistent model by its prior, and the probability of a pit in a room is the weighted fraction of consistent models that have one:

P(pit in X | percepts) = Σconsistent models with a pit in X 0.2#pits 0.8#no-pits  /  Σall consistent models 0.2#pits 0.8#no-pitsOnly rooms next to visited rooms matter; the others cancel out.

In the book's example (breezes in [1,2] and [2,1]), this gives about 0.31 for [1,3] and [3,1] and 0.86 for [2,2]. Load Book: breezy start in the explorer above to see these numbers appear. The Python agent computes exactly this in pit_probabilities(): it is model checking with weights.

4.8Do LLMs have a knowledge base?

Claude knows a vast amount, but not in the form of this chapter. Its knowledge is implicit: spread across billions of numerical weights learned from text, not stored as sentences it can enumerate. That has consequences you should design for:

  • No soundness guarantee. A logical inference procedure never derives a false conclusion from true premises. An LLM produces the most plausible continuation, which is usually right but can be fluent and wrong ("hallucination"). It also cannot list everything it "knows" or prove that it does not know something.
  • No TELL after training. You cannot add a fact to the weights during a conversation. What plays the role of TELL is the context: put the fact in the prompt or a tool result, and the model can use it for the rest of the conversation.
  • Grounding with tools. Good agents compensate the way a knowledge-based agent would: they look things up (read the file, search the documentation: retrieval, often called RAG) and check (run the tests, call a calculator, run a SAT solver or theorem prover as a tool) instead of trusting recall.
Design rule for your agents

Use the LLM for what it is good at (understanding requests, choosing which tool to use, writing code and explanations) and give it tools for what logic and computation are good at (exact facts, proofs, arithmetic, checking constraints). A safety check such as "never drive closer than 15 cm to an obstacle" belongs in code, not in the prompt (lesson 08).

"""
wumpus_kb.py - a knowledge-based agent in the wumpus world (AIMA Chapter 7, and the
probabilistic version in 3e Section 13.6 / 4e Section 12.7).

The agent never sees pits or the wumpus. It only feels a Breeze next to a pit and smells a
Stench next to the wumpus. From those percepts it reasons about which squares are safe.

Inference here is MODEL CHECKING (AIMA's TT-ENTAILS idea): enumerate every possible world
(every placement of pits and of the one wumpus on the squares we haven't visited), keep the
ones consistent with what we have perceived, and ask:

    "Is there a pit in [x,y]?"  is entailed false  <=>  no consistent world has a pit there.

Weighting each consistent world by its prior (each square has a pit with probability 0.2)
gives the probability of a pit, exactly as in the book's probabilistic wumpus example.

Run:  python wumpus_kb.py            (the world of AIMA Figure 7.2)
No packages needed.
"""
import itertools
from collections import deque

N = 4
PIT_PRIOR = 0.2


def neighbors(c):
    x, y = c
    for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
        if 1 <= x + dx <= N and 1 <= y + dy <= N:
            yield (x + dx, y + dy)


class World:
    """The true environment (the agent can't look inside)."""

    def __init__(self, pits, wumpus, gold):
        self.pits, self.wumpus, self.gold = set(pits), wumpus, gold

    def percept(self, c):
        return {
            "breeze": any(n in self.pits for n in neighbors(c)),
            "stench": any(n == self.wumpus for n in neighbors(c)),
            "glitter": c == self.gold,
        }


class KnowledgeBase:
    def __init__(self):
        self.visited = {}           # square -> percept dict (what TELL put into the KB)

    def tell(self, square, percept):
        self.visited[square] = percept

    def unknown(self):
        return [(x, y) for x in range(1, N + 1) for y in range(1, N + 1) if (x, y) not in self.visited]

    # ---- ASK: probability of a pit / the wumpus in each unknown square -----------------
    def pit_probabilities(self):
        frontier = sorted({n for v in self.visited for n in neighbors(v) if n not in self.visited})
        weights = {c: 0.0 for c in frontier}
        total = 0.0
        for bits in itertools.product((False, True), repeat=len(frontier)):    # 2^|frontier| worlds
            pits = {c for c, b in zip(frontier, bits) if b}
            if all(any(n in pits for n in neighbors(v)) == p["breeze"] for v, p in self.visited.items()):
                w = 1.0
                for b in bits:
                    w *= PIT_PRIOR if b else 1 - PIT_PRIOR
                total += w
                for c in pits:
                    weights[c] += w
        probs = {c: weights[c] / total for c in frontier}
        for c in self.unknown():           # squares not next to anything we've felt: just the prior
            probs.setdefault(c, PIT_PRIOR)
        return probs

    def wumpus_probabilities(self):
        cands = [c for c in self.unknown()
                 if all((c in neighbors(v)) == p["stench"] for v, p in self.visited.items())]
        return {c: (1 / len(cands) if c in cands else 0.0) for c in self.unknown()}

    def safe_squares(self):
        pp, wp = self.pit_probabilities(), self.wumpus_probabilities()
        return {c for c in self.unknown() if pp[c] == 0 and wp[c] == 0}


def route(start, goal, allowed):
    """Breadth-first path through squares we know are safe."""
    q, parent = deque([start]), {start: None}
    while q:
        c = q.popleft()
        if c == goal:
            break
        for n in neighbors(c):
            if n not in parent and (n in allowed or n == goal):
                parent[n] = c
                q.append(n)
    if goal not in parent:
        return None
    path, c = [], goal
    while c:
        path.append(c)
        c = parent[c]
    return path[::-1]


def show(kb, here):
    pp, wp = kb.pit_probabilities(), kb.wumpus_probabilities()
    for y in range(N, 0, -1):
        cells = []
        for x in range(1, N + 1):
            c = (x, y)
            if c == here:
                cells.append("  A  ")
            elif c in kb.visited:
                p = kb.visited[c]
                cells.append(" " + ("B" if p["breeze"] else ".") + ("S" if p["stench"] else ".") + "  ")
            elif pp[c] == 0 and wp[c] == 0:
                cells.append(" OK  ")
            else:
                cells.append(f"{max(pp[c], wp[c]):.2f} ")
        print("   |" + "|".join(cells) + "|")


def run(world, max_steps=30):
    kb, here, path = KnowledgeBase(), (1, 1), [(1, 1)]
    for step in range(max_steps):
        p = world.percept(here)
        kb.tell(here, p)                                         # TELL the KB what we perceive
        print(f"\nStep {step}: at {here}, percept {p}")
        if p["glitter"]:
            print("Glitter! Grab the gold and climb out the way we came.")
            return path
        show(kb, here)
        safe = kb.safe_squares()                                 # ASK the KB
        known_safe = set(kb.visited) | safe
        options = [(len(route(here, c, known_safe) or []), c) for c in safe]
        options = [o for o in options if o[0] > 0]
        if options:
            _, target = min(options)
            print(f"   safe unexplored squares: {sorted(safe)}  ->  go to {target}")
        else:
            pp, wp = kb.pit_probabilities(), kb.wumpus_probabilities()
            reachable = [c for c in kb.unknown() if route(here, c, set(kb.visited))]
            target = min(reachable, key=lambda c: 1 - (1 - pp[c]) * (1 - wp[c]))
            risk = 1 - (1 - pp[target]) * (1 - wp[target])
            print(f"   nothing is provably safe; least risky square is {target} (risk {risk:.2f})")
            if risk > 0.5:
                print("   too risky: climb out without the gold")
                return path
        leg = route(here, target, known_safe)
        path += leg[1:]
        here = target
        if here in world.pits or here == world.wumpus:
            print(f"   ... and the agent died in {here}")
            return path
    return path


if __name__ == "__main__":
    # AIMA Figure 7.2: pits in (3,1), (3,3), (4,4); wumpus in (1,3); gold in (2,3)
    world = World(pits={(3, 1), (3, 3), (4, 4)}, wumpus=(1, 3), gold=(2, 3))
    print("Legend: A agent, B breeze felt, S stench felt, OK provably safe, number = risk")
    run(world)
Exercises
  1. Add the arrow: if the wumpus's location is certain (probability 1), shoot it from a neighboring room and mark it dead. When does this unlock rooms that were otherwise unreachable?
  2. Replace the enumeration in pit_probabilities with a SAT solver query (e.g. the pycosat package): KB ∧ Px,y unsatisfiable ⇒ the room has no pit.
  3. Run 1,000 random worlds. How often does the agent get the gold, die, or climb out empty-handed? How does it change if the risk threshold is 0.3 instead of 0.5?
