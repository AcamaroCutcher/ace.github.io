1.1What is an agent?

Russell and Norvig build the whole book around one idea: an agent is anything that perceives its environment through sensors and acts on that environment through actuators. That is all. The definition is deliberately broad, so that a thermostat, a chess program, a robot vacuum, a self-driving car and an AI coding assistant are all described by the same picture.

At each moment the agent receives a percept: what its sensors report right now. Everything it has ever perceived is its percept sequence. Its job is to choose an action. The question the whole field tries to answer is: what should go in the box with the question mark?

Key idea

An agent is defined by what it perceives, what it can do, and how it chooses. AI, in the book's framing, is the study of how to build the chooser: the agent program.

Why this matters for you

When you build an agent later, the first design decision is exactly this table: which percepts will it get, and which actions will it be allowed to take? For an LLM agent, the actions are the tools you give it, and that choice is also your main safety lever.

1.2Agent function vs. agent program

The book separates two things that are easy to blur:

  • The agent function is a mathematical object: a table that says which action to take for every possible percept sequence. It describes behavior from the outside.
  • The agent program is real code that runs on a physical architecture (a computer with sensors and motors). It receives one percept at a time and returns one action. It implements the function.

Why not just write the table? Because it is astronomically large. In the two-square vacuum world below there are 4 possible percepts. An agent that lives for T steps needs one row for every possible history: 4 + 4² + … + 4T rows. That is 1,364 rows for five steps and about 1.4 million for ten. For a taxi's camera, the table would have more rows than there are atoms in the universe. The challenge of AI is to write small programs that produce rational behavior, not giant lookup tables.

rows(T) = P + P2 + … + PTP possible percepts, lifetime T steps. With P = 4: T = 1 → 4, T = 2 → 20, T = 5 → 1,364, T = 10 → 1,398,100, T = 20 → 1.47 × 10¹².

1.3The vacuum world

The book's first example is tiny on purpose: two squares, A and B, each clean or dirty, and a vacuum that is in one of them. The percept is [location, status], e.g. [A, Dirty]. The actions are Left, Right, Suck (and doing nothing, NoOp). The performance measure awards one point for each clean square at each time step.

1.5Rationality: doing the right thing

An agent is judged by the consequences of its behavior. The designer writes down a performance measure that scores sequences of environment states. Then the book defines:

For each possible percept sequence, a rational agent should select an action that is expected to maximize its performance measure, given the evidence provided by the percept sequence and whatever built-in knowledge the agent has.Russell & Norvig, AIMA §2.2

Four things determine what is rational at any moment: the performance measure, the agent's prior knowledge of the environment, the actions it can perform, and its percept sequence so far. Some consequences that trip people up:

  • Rational ≠ omniscient. A rational agent maximizes expected performance given what it knows. If you cross the street carefully and a piece of an airplane falls on you, you were still rational.
  • Rational ≠ successful. Good decisions can have bad outcomes; judge the decision by the information available when it was made.
  • Measure what you want, not how you want it done. If you reward a vacuum for the amount of dirt it sucks up, a rational vacuum dumps dirt and sucks it up again. Reward clean floors instead. (The same problem appears with LLMs as reward hacking, e.g. "make the tests pass" solved by deleting the tests.)
  • Information gathering and learning are part of rationality. Looking before crossing the road is a rational action. An agent that relies only on its designer's built-in knowledge lacks autonomy.
Key idea

"Rational" is always relative to a performance measure, the agent's knowledge, its actions and its percepts. Change any one (try the Moving costs 1 point switch above) and the rational action can change.

1.7Seven properties of environments

The environment, much more than the agent, decides how hard the problem is. The book classifies environments along these dimensions; each one tells you which techniques you will need:

DimensionEasy endHard endWhat the hard end forces you to build
ObservabilityFully observablePartially observableMemory, internal state, belief tracking (lessons 02, 04)
AgentsSingle-agentMultiagentGame theory, communication, modeling others
DeterminismDeterministicStochastic / nondeterministicProbabilities, expected utility, contingency plans (lesson 05)
EpisodesEpisodicSequentialPlanning ahead; actions have long-term consequences (lessons 03, 05)
ChangeStaticDynamicFast decisions; thinking too long is itself an action
States & timeDiscreteContinuousControl theory, function approximation (lesson 09)
KnowledgeKnown rulesUnknown rulesLearning and exploration (lesson 05)
Hardest case

The real world is partially observable, multiagent, stochastic, sequential, dynamic, continuous and partly unknown. That is why driving and robotics are hard, and why a robot needs fast reflexes underneath slow planning (lesson 09).

"""
vacuum_world.py - AIMA Chapter 2 in runnable form.

The two-square vacuum world (AIMA 3e/4e, Section 2.1, Figure 2.2) and four agent programs
from Section 2.4:

    TableDrivenAgent      looks the whole percept sequence up in a table (Figure 2.7)
    SimpleReflexAgent     acts on the current percept only (Figure 2.8 / 2.10)
    ModelBasedReflexAgent remembers what it has seen (Figure 2.12)
    RandomAgent           a baseline: picks any action

The environment awards +1 for every clean square after every time step (the performance
measure the book proposes) and, optionally, charges for each move.

Run:  python vacuum_world.py
No packages needed (Python 3.8+).
"""
import itertools
import random

LOCATIONS = ("A", "B")
ACTIONS = ("Left", "Right", "Suck", "NoOp")


# ----------------------------------------------------------------------------------------
# The environment: owns the true state. The agent only ever sees percepts.
# ----------------------------------------------------------------------------------------
class VacuumEnvironment:
    def __init__(self, dirt, location, move_cost=0.0):
        self.status = dict(dirt)          # {"A": "Dirty", "B": "Clean"}
        self.location = location          # where the agent is
        self.move_cost = move_cost
        self.score = 0.0

    def percept(self):
        """What the sensors report: [location, status of that square]. Partial observability."""
        return (self.location, self.status[self.location])

    def execute(self, action):
        """Transition model: change the world according to the action."""
        if action == "Suck":
            self.status[self.location] = "Clean"
        elif action == "Right":
            self.location = "B"
            self.score -= self.move_cost
        elif action == "Left":
            self.location = "A"
            self.score -= self.move_cost
        # NoOp does nothing

    def step(self, agent_program):
        p = self.percept()
        a = agent_program(p)
        self.execute(a)
        # performance measure: one point per clean square per time step
        self.score += sum(1 for s in self.status.values() if s == "Clean")
        return p, a


# ----------------------------------------------------------------------------------------
# Agent programs. Each is a function: percept -> action (it may keep private state).
# ----------------------------------------------------------------------------------------
def TableDrivenAgent(table):
    """AIMA Figure 2.7. Appends each percept to the history and looks the whole history up."""
    percepts = []

    def program(percept):
        percepts.append(percept)
        return table.get(tuple(percepts), "NoOp")

    return program


def SimpleReflexAgent():
    """AIMA Figure 2.8 (REFLEX-VACUUM-AGENT): condition-action rules on the current percept."""
    def program(percept):
        location, status = percept
        if status == "Dirty":
            return "Suck"
        if location == "A":
            return "Right"
        return "Left"

    return program


def ModelBasedReflexAgent():
    """AIMA Figure 2.12. Keeps a model of both squares, so it can stop when it knows all is clean."""
    model = {"A": None, "B": None}       # None = never seen

    def program(percept):
        location, status = percept
        model[location] = status          # UPDATE-STATE from the percept
        if status == "Dirty":
            model[location] = "Clean"     # ...and from the predicted effect of our action
            return "Suck"
        if model["A"] == model["B"] == "Clean":
            return "NoOp"                 # rule: everything is known to be clean -> rest
        return "Right" if location == "A" else "Left"

    return program


def RandomAgent(seed=None):
    rng = random.Random(seed)
    return lambda percept: rng.choice(ACTIONS)


# ----------------------------------------------------------------------------------------
# Experiments
# ----------------------------------------------------------------------------------------
def all_start_states():
    """Every combination of dirt and start location: 2 x 2 x 2 = 8 worlds."""
    for a, b, loc in itertools.product(("Clean", "Dirty"), ("Clean", "Dirty"), LOCATIONS):
        yield {"A": a, "B": b}, loc


def evaluate(make_agent, steps=10, move_cost=0.0):
    """Average score over all 8 start states, like AIMA Exercise 2.8 (3e) asks for."""
    total = 0.0
    for dirt, loc in all_start_states():
        env = VacuumEnvironment(dirt, loc, move_cost)
        agent = make_agent()
        for _ in range(steps):
            env.step(agent)
        total += env.score
    return total / 8


def trace(make_agent, dirt, loc, steps=6):
    env = VacuumEnvironment(dirt, loc)
    agent = make_agent()
    print(f"  start: agent in {loc}, squares {dirt}")
    for t in range(steps):
        p, a = env.step(agent)
        print(f"  t={t}  percept={p}  ->  action={a:5s}  score={env.score:.0f}")


if __name__ == "__main__":
    print("Simple reflex agent, both squares dirty, starting in A:")
    trace(SimpleReflexAgent, {"A": "Dirty", "B": "Dirty"}, "A")

    # A table for the first two percepts only: it shows why tables explode.
    # With P possible percepts and lifetime T the table has sum_{t=1..T} P^t rows.
    P = 4  # (A|B) x (Clean|Dirty)
    print("\nTable-driven agent: rows needed for lifetime T =", [sum(P**t for t in range(1, T + 1)) for T in (1, 2, 5, 10, 20)])

    print("\nAverage score over the 8 start states (10 steps):")
    for cost in (0.0, 1.0):
        print(f"  move cost = {cost}")
        for name, make in [("simple reflex", SimpleReflexAgent),
                           ("model-based reflex", ModelBasedReflexAgent),
                           ("random (seed 0)", lambda: RandomAgent(0))]:
            print(f"    {name:20s} {evaluate(make, 10, cost):6.2f}")

Exercises
  1. Make dirt reappear: in VacuumEnvironment.step, after the action, make each clean square dirty with probability 0.1. Which agent wins now, and why does the model-based agent's "everything is clean → rest" rule become a weakness?
  2. Write a TableDrivenAgent table that behaves like the reflex agent for the first two steps. How many entries did you need?
  3. Change the performance measure to "+10 per Suck on a dirty square". Write an agent that games it if dirt can reappear. This is the vacuum version of reward hacking.
